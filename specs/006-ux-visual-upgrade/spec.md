# Feature Specification: 体验与视觉体系升级

**Feature Branch**: `006-ux-visual-upgrade`

**Created**: 2026-07-16

**Status**: Draft

**Input**: User description: "这是 Watson 的第六轮迭代，命名为「体验与视觉体系升级」。前五轮功能已齐备，本轮不新增任何业务能力，只系统性提升交互体验与视觉设计质量。硬性边界：不改变任何数据模型、后端接口、业务规则与既有功能行为，仅改进前端的呈现、反馈与美观度；任何改动都不得回归破坏 001~005 已验证的功能。"

## Clarifications

### Session 2026-07-16

- Q: 设计风格基调与强调色策略？ → A: 延续现有「简洁 + 科技感」气质；强调色沿用浅色主题蓝、深色主题 NVIDIA 绿；本轮做体系化收敛而非推倒重来。
- Q: 动效强度与时长目标？ → A: 克制、快速（150–250ms），以顺滑为目标、非炫技；须遵守系统「减少动态效果」偏好。
- Q: 重要度/紧急度可视化首选形式？ → A: 颜色梯度 + 强度条组合，数字保留为辅助；具体组件形态由 plan 阶段敲定。
- Q: 坐标图象限命名与轴标注？ → A: 采用艾森豪威尔四象限语义（立即做 / 计划做 / 授权做 / 减少做），原点 (5,5) 沿用；坐标轴上保留「重要度」「紧急度」轴名以标明朝向。
- Q: 空状态视觉深度要求？ → A: 图标级即可，不必强求定制插画；引导文案与主操作按钮是重点。
- Q: 操作成功反馈形态？ → A: 轻量 toast，自动消失，不打断操作。
- Q: 若某条视觉需求必须动后端？ → A: 不得擅自改动；在 plan 中单列标注并单独确认后再议。
- Q: 顶栏分段控件是否包含垃圾箱？ → A: 否。SegmentedControl 仅日/周/月/全部；垃圾箱为右侧独立入口（与主题/AI 语义分组，见 US4）。
- Q: ViewTimeNav 是否迁入顶栏中区？ → A: 否。ViewTimeNav 留在日/周/月视图内；顶栏中区为 SegmentedControl + AnchorDateControl。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 全站视觉规范一致 (Priority: P1)

作为所有者，我希望 Watson 在延续「简洁 + 科技感」气质的前提下，于明暗主题下呈现统一、协调的视觉语言（间距、圆角、阴影、字号字重、强调色及其交互状态），以便界面不再零散、更有整体设计感。

**Why this priority**: 视觉规范是本轮所有改动的底座；无统一令牌则后续导航、卡片、坐标图等升级无法形成一致气质。

**Independent Test**: 抽查顶栏、卡片、按钮、弹层、登录页等代表性界面，确认同类控件使用一致的间距阶梯、圆角档位、阴影层级、字号字重与强调色常态/悬停/按下/浅色底状态；深浅主题下均可辨认。

**Acceptance Scenarios**:

1. **Given** 所有者浏览任意主要界面，**When** 对比按钮、输入框、卡片、分段控件等同类元素，**Then** 间距、圆角、阴影、字号与字重遵循同一套可见规范，无「同类型控件样式各异」的明显违和。
2. **Given** 可交互的强调色元素（主按钮、选中分段、链接式操作等），**When** 依次经历默认、悬停、按下状态，**Then** 各状态视觉变化一致且可区分，浅色底上的强调色用法与主面上的用法协调。
3. **Given** 浅色与深色主题，**When** 切换并浏览同一页面，**Then** 同一语义控件在两种主题下保持对应层级关系（标题强于正文、卡片强于背景等），无某主题下大面积不可读或对比失衡。
4. **Given** 所有者对比升级前后整体气质，**When** 浏览主界面，**Then** 仍识别为同一产品（简洁 + 科技感），强调色分别为浅色主题蓝与深色主题 NVIDIA 绿，本轮为体系化收敛而非推倒重来的全新风格。

### User Story 2 - 交互过渡与无障碍动效偏好 (Priority: P1)

作为所有者，我希望主题切换、面板开合、悬停反馈与弹层出现/消失具有平顺过渡，而非瞬间硬切；同时在我开启系统「减少动态效果」时，界面仍可用且不造成不适。

**Why this priority**: 与 P1 视觉规范并列构成「质感」基础；硬切会削弱升级感知，忽略减少动态效果则违背无障碍预期。

**Independent Test**: 切换明暗主题、打开/关闭弹层与侧边面板、悬停主要控件，观察过渡是否柔和；在系统开启「减少动态效果」后重复，确认动效被抑制或替换为即时切换且功能不受影响。

**Acceptance Scenarios**:

1. **Given** 所有者切换明暗主题，**When** 主题变更完成，**Then** 主色与背景色变化带有可感知的颜色过渡，而非整页瞬间跳变。
2. **Given** 所有者打开或关闭弹层、浮层、侧边 AI 面板等覆盖层，**When** 交互完成，**Then** 出现与消失带有柔和过渡（如淡入淡出或适度位移），不突兀闪现。
3. **Given** 所有者将指针悬停在可点击控件上，**When** 进入/离开悬停态，**Then** 背景、边框或阴影等反馈带有短促平滑过渡（常态时长约 150–250ms，克制顺滑、非炫技）。
4. **Given** 操作系统或浏览器已启用「减少动态效果」（prefers-reduced-motion），**When** 执行上述主题、弹层、悬停相关操作，**Then** 系统尊重该偏好：大幅缩短或取消非必要动画，**不**因此丢失功能或阻塞操作。

### User Story 3 - 顶栏三区布局与视图分段控件 (Priority: P2)

作为所有者，我希望顶部导航栏按「品牌与搜索 / 视图切换与日期导航 / 操作区」清晰分区，视图切换呈分段式容器控件、搜索框宽度合理，以便快速理解当前所在视图并完成检索与导航。

**Why this priority**: 顶栏是使用最高频的壳层；布局失衡会直接影响每日操作效率，且是本轮最显性的结构改进之一。

**Independent Test**: 在各常规视图查看顶栏三区是否清晰；在日/周/月/全部间切换时观察分段选中态（垃圾箱为右侧独立入口，不在分段控件内）；搜索框默认宽度适中、聚焦时可扩展；顶栏日期控件（AnchorDate）与视图内 ViewTimeNav 仍符合 005 行为。

**Acceptance Scenarios**:

1. **Given** 所有者打开任意主界面，**When** 查看顶栏，**Then** 可识别三个逻辑区域：左侧为品牌标识与搜索（及新建）、中部为日/周/月/全部分段控件与 AnchorDateControl、右侧为操作按钮组（含独立垃圾箱入口）。
2. **Given** 视图分段控件，**When** 在日/周/月/全部之间切换，**Then** 呈现于统一容器内的分段式样式；当前选中项与未选中项使用同一视觉语言且对比清晰，**不**出现选中与未选落差突兀的「跳色」违和感；**垃圾箱不作为该分段控件的选项**（进入垃圾箱仍经右侧独立入口，见 US4）。
3. **Given** 搜索框处于未聚焦状态，**When** 查看顶栏比例，**Then** 搜索框宽度收窄至不挤压中部与右侧；**When** 聚焦搜索，**Then** 可适度展开以便输入，且展开过程平顺。
4. **Given** 005 已定义的日期导航与视图行为（如日/周/月步进在视图内 ViewTimeNav、全部视图日期不影响列表、垃圾箱无日期控件等），**When** 本轮视觉重组后操作，**Then** 行为与 005 一致，仅呈现方式改进；ViewTimeNav **不**迁入顶栏。

### User Story 4 - 操作区语义分组 (Priority: P2)

作为所有者，我希望顶栏右侧把「进入垃圾箱」与「切换主题 / AI 面板」等偏好类操作在视觉上区分开，以免危险或归档类入口与日常设置混为一谈。

**Why this priority**: 语义分组降低误触心理成本，并与 005 拖拽删除进箱形成一致的「垃圾箱」心智。

**Independent Test**: 查看顶栏右侧是否通过间距、分隔线或分组容器区分垃圾箱入口与主题、AI 等控件；拖拽删除与点击进入垃圾箱仍按 004/005 语义工作。

**Acceptance Scenarios**:

1. **Given** 所有者查看顶栏右侧，**When** 辨认各按钮，**Then** 「进入垃圾箱」与「切换明暗主题」「开关 AI 侧边栏」等分属不同视觉分组（例如组间分隔或间距阶梯），垃圾箱入口的层级与危险/归档语义相匹配。
2. **Given** 所有者点击垃圾箱入口或使用拖拽删除，**When** 完成操作，**Then** 业务行为与第四、五轮一致（删除进箱、红圆标记、恢复与永久删除路径不变），**仅**视觉与反馈升级。

### User Story 5 - 卡片优先级可视化与信息层级 (Priority: P2)

作为所有者，我希望日程卡片上的重要度与紧急度（0～10）以直观图形呈现而非裸数字，且卡片具备分类色带、清晰的信息层级，并在深浅主题下都与背景有足够对比，以便一眼判断优先级与类别。

**Why this priority**: 卡片是核心信息载体；可读性直接决定排序与坐标图以外的日常扫视效率。

**Independent Test**: 打开含不同重要度/紧急度与分类的卡片，确认图形化指示器、左缘分类色带、标题/时间/标签/优先级层级；切换主题检查卡片抬升感与阴影；数字可作辅助但非唯一表达。

**Acceptance Scenarios**:

1. **Given** 卡片具有重要度与紧急度数值（0～10），**When** 所有者浏览卡片，**Then** 以颜色梯度 + 强度条组合表达高低（低值偏冷/淡、高值偏醒目），数字仅作辅助；裸数字「重要5 紧急5」式主展示**不得**再作为唯一呈现。
2. **Given** 卡片有关联分类，**When** 查看卡片，**Then** 存在分类向的颜色标识（如左侧色带），与标题、时间、标签、优先级区分的视觉层级：标题最突出，时间次之，标签与优先级再次之。
3. **Given** 浅色或深色主题，**When** 卡片置于主背景上，**Then** 卡片通过适度背景抬升与阴影（或等效层次手段）与背景清晰区分，深色模式下**不**出现卡片「贴平」难以辨认的情况。
4. **Given** 卡片数据与 001～005 相同，**When** 仅改变呈现，**Then** 完成勾选、拖拽、打开详情、搜索命中等行为与升级前一致。

---

### User Story 6 - 完成勾选控件重设计 (Priority: P3)

作为所有者，我希望卡片上的「完成」勾选框语义清晰、悬停有反馈、勾选时有轻微确认动效，而不再像未渲染的灰色占位方块。

**Why this priority**: 完成是高频操作；控件质感影响操作信心，但依赖 P2 卡片整体规范。

**Independent Test**: 悬停与点击完成框，观察未选/选中/悬停态与轻动效；完成后卡片仍按既有规则归档或标记，数据路径不变。

**Acceptance Scenarios**:

1. **Given** 活跃日程卡片，**When** 查看完成勾选框，**Then** 呈现为明确的可选/已选控件（非空白灰块），边界与图标语义清晰。
2. **Given** 指针悬停于未完成项的勾选框，**When** 进入悬停态，**Then** 有可见反馈（如边框、背景或光标提示）。
3. **Given** 所有者点击勾选完成，**When** 状态变为已完成，**Then** 有轻微确认动效（在未开启减少动态效果时）；业务结果与第五轮及此前完成语义一致。
4. **Given** 系统启用减少动态效果，**When** 勾选完成，**Then** 动效被抑制但状态切换立即可见。

---

### User Story 7 - 优先级坐标图四象限可读化 (Priority: P2)

作为所有者，我希望日视图右侧与全部视图的优先级坐标图呈现为可理解的「重要—紧急」四象限矩阵：四象限有淡背景分区与名称标签，坐标轴与原点清晰，深浅主题下均可读，以便理解每个象限含义。

**Why this priority**: 第四、五轮已提供坐标能力，但十字线图对用户解释性不足；本轮在不改数据与取数规则前提下提升图表可读性。

**Independent Test**: 在日视图常驻区与全部视图浮层中查看坐标图；确认四象限背景与标签（如立即做/计划做/授权做/减少做或同等易懂文案）、轴线与原点 5/5 可见；切换主题后仍可读。

**Acceptance Scenarios**:

1. **Given** 日视图右侧常驻坐标区域或全部视图打开的坐标浮层，**When** 所有者查看图表，**Then** 可见横轴标注「紧急度」、纵轴标注「重要度」、原点 (5,5) 参照，轴线在深色主题下**不**近乎不可见。
2. **Given** 坐标图区域，**When** 查看四象限，**Then** 各象限有淡色背景分区及艾森豪威尔语义名称标签：立即做、计划做、授权做、减少做（全站一致）。
3. **Given** 005 规定的取数范围（如日视图仅当日活跃卡、全部视图含活跃卡等），**When** 仅升级视觉，**Then** 点位数据与过滤规则与第五轮一致，**不**新增坐标交互能力或数据维度。

### User Story 8 - 坐标图点位标识与稀少数据说明 (Priority: P3)

作为所有者，我希望坐标图上的点能对应到具体任务，悬停时有精致信息浮层；在数据很少时看到引导说明而非大片空白像出错。

**Why this priority**: 在 P7 矩阵可读基础上，提升单点可识别性与空疏场景的信心。

**Independent Test**: 日/全部视图坐标图上悬停点位查看浮层；仅 0～1 个点时显示轻量说明文案；点击行为仍符合第四轮（无额外导航要求）。

**Acceptance Scenarios**:

1. **Given** 坐标图上存在一个或多个点，**When** 所有者悬停某点，**Then** 出现信息浮层，至少包含可识别该任务的标题或等价标识，以及重要度/紧急度等关键信息，样式与全站浮层规范一致。
2. **Given** 坐标图可见区域内点数较少（含零个或一个），**When** 所有者查看图表，**Then** 显示轻量说明性文案（如解释当前分布或如何添加日程），**不**留突兀无说明的大片空白。
3. **Given** 第四轮关于坐标点击无额外行为的约定，**When** 本轮升级后点击点或空白，**Then** **不**引入新的导航或编辑行为（除非未来单独立项）。

---

### User Story 9 - 空状态、加载骨架与操作反馈 (Priority: P2)

作为所有者，我希望各视图在无数据、搜索无结果、垃圾箱为空时有图标/插画、引导文案与主操作入口；创建/完成/删除/恢复等操作有轻量成功提示；加载中以骨架占位替代空白闪烁，以便页面始终「有反馈」、不像未完成品。

**Why this priority**: 空状态与操作反馈直接塑造产品完成度；覆盖主路径与边缘视图（含垃圾箱、搜索）。

**Independent Test**: 逐一打开无数据的日/周/月/全部/垃圾箱视图及空搜索；执行创建、完成、删除、恢复并观察成功提示；刷新或切换视图时见骨架而非白屏闪烁。

**Acceptance Scenarios**:

1. **Given** 某视图当前无任何可展示日程（含垃圾箱无已删项、搜索无匹配），**When** 所有者查看主内容区，**Then** 显示空状态组合：图标（不必定制插画）+ 简短引导文案 + 指向主操作（如创建日程、调整筛选或返回常规视图）的按钮入口；文案与主操作按钮是视觉重点。
2. **Given** 所有者成功创建、完成、删除或恢复日程，**When** 操作成功，**Then** 出现轻量 toast 成功反馈，文案表意明确，自动消失且不打断后续操作。
3. **Given** 日程数据尚在加载，**When** 所有者进入或切换视图，**Then** 主列表或卡片区域以占位骨架呈现，**不**出现长时间无内容的空白闪烁。
4. **Given** 操作失败（网络或校验错误等既有路径），**When** 失败发生，**Then** 仍按既有错误提示逻辑处理；本轮**不**削弱错误可见性。

### User Story 10 - 拖拽进垃圾箱的放置反馈 (Priority: P3)

作为所有者，我希望把卡片拖向顶栏垃圾箱时，垃圾箱作为放置目标会有高亮或激活反馈，以便明确「松手即删除」。

**Why this priority**: 005 已支持拖拽删除；本轮仅补强目标 affordance，不改变删除语义与无二次确认规则。

**Independent Test**: 从日/周/月/全部拖活跃卡向垃圾箱，观察拖入过程中的高亮；松手后行为与 005 一致；未拖入垃圾箱则无反馈激活。

**Acceptance Scenarios**:

1. **Given** 所有者在支持拖拽删除的视图上拖动活跃卡片，**When** 拖曳进入垃圾箱放置热区，**Then** 垃圾箱入口呈现明显激活态（高亮、描边或背景变化等），提示可放置。
2. **Given** 拖曳离开垃圾箱热区或取消拖拽，**When** 未在垃圾箱上松手，**Then** 激活态消退，卡片不进箱。
3. **Given** 在垃圾箱热区上松手，**When** 完成放置，**Then** 仍按第五轮：等同删除进箱、无二次确认、常规视图消失；与详情内二次确认删除路径并存。

### User Story 11 - 全局排版与登录页第一印象 (Priority: P3)

作为所有者，我希望全站正文与标题排版节奏统一；登录页构图平衡、品牌标题质感得体、验证码输入框对比度足够且带输入引导，以便首次访问与每次登录都专业可信。

**Why this priority**: 登录页是品牌门面；全局排版支撑长期阅读舒适度，但不阻塞核心日程操作路径。

**Independent Test**: 对比各页标题与正文层级；在明暗主题下查看登录页布局、标题样式、验证码框与引导文案；验证码登录流程与 001 鉴权语义不变。

**Acceptance Scenarios**:

1. **Given** 所有者浏览日程主界面与登录页，**When** 对比标题、副标题与正文，**Then** 字号与字重层级遵循全站统一节奏，无页面「字号体系脱节」。
2. **Given** 未登录用户打开登录页，**When** 查看整体构图，**Then** 品牌区、表单区与下方备案占位（005）布局平衡，**不**出现中下部大面积无意义空白破坏重心。
3. **Given** 登录页品牌标题，**When** 查看视觉效果，**Then** 质感克制专业，**不**使用过艳或廉价感的发光描边配色。
4. **Given** 四字符验证码输入，**When** 用户准备输入，**Then** 输入框与背景对比充足、易于辨认，并配有简短输入引导文字（说明输入四字符验证码）；校验规则与会话行为与宪法及既有实现一致。

---

### Edge Cases

- 当系统启用「减少动态效果」时，主题过渡、弹层、勾选与拖拽反馈均须降级为即时或极简变化，功能与 001～005 行为不变。
- 当单张卡片重要度或紧急度为 0 或 10 端点时，可视化指示器仍须可辨（不塌缩为不可见）。
- 当卡片分类缺失或分类无色值时，左缘色带须有中性回退样式，**不**破坏布局。
- 当坐标图点密集重叠时，悬停浮层须能区分或展示聚合提示，避免完全无法辨认。
- 当搜索框聚焦展开导致窄屏宽度不足时，布局须优雅折行或收缩非关键元素，**不**遮挡视图切换或阻塞操作。
- 当用户快速连续触发成功提示时，提示**不**严重堆叠遮挡界面（合并、替换或队列消失均可接受）。
- 当加载极快时，骨架闪现须可接受（可极短显示），**不**造成长时间假加载。
- 深色主题下四象限背景分区与轴线对比须单独验证，避免「看得见点却看不见象限」。
- 本轮**不得**改变数据模型、API 契约、鉴权、完成/删除/恢复/搜索/视图过滤等业务规则；回归测试须覆盖 001～005 全部已验证功能。
- 若实现过程中发现某条视觉需求**必须**依赖后端或数据模型变更，MUST 在 plan 中单列标注并单独确认，**不得**擅自扩展范围。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在全站应用统一的视觉规范，涵盖间距阶梯、圆角档位、阴影层级、字号字重层级，以及强调色在常态、悬停、按下与浅色底场景下的一致用法；设计风格 MUST 延续「简洁 + 科技感」，强调色沿用浅色主题蓝与深色主题 NVIDIA 绿，本轮为体系化收敛而非推倒重来。
- **FR-002**: 系统 MUST 对主题切换、面板开合、悬停态变化及弹层出现/消失提供平顺视觉过渡（常态时长约 150–250ms，克制顺滑、非炫技），并 MUST 在用户启用系统「减少动态效果」偏好时尊重该设置，以即时或极简变化替代非必要动画且不损失功能。
- **FR-003**: 顶栏 MUST 重组为三个清晰逻辑区：品牌与搜索、视图切换与 AnchorDate、操作区；布局在常见桌面与响应式宽度下均可辨认三区。日/周/月的前一/当前/后一导航（ViewTimeNav）MUST 留在各视图内，MUST NOT 迁入顶栏。
- **FR-004**: 日/周/月/全部的视图切换 MUST 呈现为容器内的分段式控件；选中与未选项 MUST 使用统一视觉语言，避免突兀的选中/未选落差。垃圾箱 MUST NOT 作为该分段控件的选项（独立入口见 FR-006）。
- **FR-005**: 搜索框 MUST 默认保持合理收窄宽度，并 MAY 在聚焦时平滑展开；展开不得改变搜索业务行为（与 003 一致）。
- **FR-006**: 顶栏操作区 MUST 将「进入垃圾箱」与主题切换、AI 面板开关等偏好类控件进行视觉分组区分。
- **FR-007**: 日程卡片 MUST 以颜色梯度 + 强度条组合表达 0～10 的重要度与紧急度；数字 MUST 仅作辅助信息，MUST NOT 作为唯一主展示（具体组件形态由 plan 阶段敲定）。
- **FR-008**: 日程卡片 MUST 通过分类向颜色标识（如左缘色带）与排版层级区分标题、时间、标签与优先级信息；卡片 MUST 在浅色与深色主题下均与页面背景保持清晰层次（适度抬升与阴影或等效手段）。
- **FR-009**: 卡片完成勾选控件 MUST 重设计为语义清晰的选框，具备悬停反馈与勾选确认动效（受减少动态效果约束）；勾选后的业务语义 MUST 与升级前一致。
- **FR-010**: 日视图常驻与全部视图浮层中的优先级坐标图 MUST 升级为四象限矩阵呈现：淡背景分区、艾森豪威尔象限标签（立即做 / 计划做 / 授权做 / 减少做）、横轴「紧急度」与纵轴「重要度」轴名、原点 (5,5)；深浅主题下轴线与分区 MUST 可读。
- **FR-011**: 坐标图上的数据点 MUST 支持悬停信息浮层，展示任务标识与关键优先级信息；在数据稀少时 MUST 展示轻量说明文案而非无说明空白。
- **FR-012**: 系统 MUST 为日、周、月、全部、垃圾箱及搜索无结果等场景提供空状态（图标即可，不必定制插画；引导文案与主操作按钮为视觉重点）。
- **FR-013**: 系统 MUST 在创建、完成、删除、恢复、永久删除等操作成功时提供轻量 toast 反馈，自动消失且不打断操作。
- **FR-014**: 数据加载过程中，主内容区 MUST 以骨架占位替代长时间空白闪烁。
- **FR-015**: 拖拽卡片至垃圾箱热区时，垃圾箱入口 MUST 呈现放置目标激活反馈；放置成功后的删除语义 MUST 与第五轮一致（进箱、无二次确认、详情删除仍二次确认）。
- **FR-016**: 全站 MUST 统一标题与正文的排版节奏；登录页 MUST 优化构图平衡、品牌标题质感、验证码输入框对比度，并补充四字符验证码输入引导文案。
- **FR-017**: 本轮 MUST NOT 修改任何数据模型、后端接口、鉴权规则、业务规则或既有功能的用户可感知行为语义（001～005 范围）；仅允许前端呈现、反馈与美观度改进。若某条视觉需求经评估必须依赖后端或数据模型变更，MUST 在 plan 中单列标注并单独确认，不得擅自扩展范围。
- **FR-018**: 交付前 MUST 对 001～005 已验证功能进行回归验证，确认无行为回退。

### Key Entities

本特性**不引入**新数据实体或持久化字段。以下仅为呈现层引用的既有概念：

- **视觉规范令牌**：间距、圆角、阴影、字号字重、强调色状态等全站复用的呈现约定（非后端实体）。
- **日程卡片（Schedule Card）**：沿用宪法与 001～005 定义；重要度 0～10、紧急度 0～10、分类、生命周期等属性不变，仅改变展示方式。
- **优先级坐标图**：日视图常驻与全部视图浮层中的二维分布视图；轴定义与取数范围沿用第四、五轮，仅提升象限语义与点位可读性。
- **空状态与反馈文案**：各视图无数据、加载中、操作成功时的界面文案与引导（非持久化数据）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在代表性界面抽查清单（顶栏、卡片、坐标图、登录页、空状态至少各 1 处）中，**100%** 的同类控件组通过「视觉规范一致性」人工评审（间距/圆角/阴影/字号/强调色状态无显著例外）。
- **SC-002**: 启用与关闭系统「减少动态效果」两种环境下，主题切换、弹层开合、完成勾选、拖拽垃圾箱反馈等核心交互 **100%** 可完成且与升级前业务结果一致；未启用减少动态效果时，上述过渡时长常态落在 **150–250ms** 区间（抽查可感知、非拖沓）。
- **SC-003**: 无日程数据的日、周、月、全部、垃圾箱及搜索无结果场景 **100%** 展示含引导文案与主操作入口的空状态，**0** 处仅空白无说明的主内容区。
- **SC-004**: 创建、完成、删除、恢复四类成功操作 **100%** 触发可感知的轻量成功反馈（用户无需打开详情即可察觉操作已生效）。
- **SC-005**: 含重要度/紧急度取值的活跃卡片 **100%** 以非纯数字的可视化方式表达优先级（数字仅作辅助时不计入失败）。
- **SC-006**: 日视图与全部视图坐标图在浅色与深色主题下，由 **5** 名以内评审员进行可读性判断时，**≥80%** 能正确说出至少两个象限的含义（或对应标签文案）。
- **SC-007**: 001～005 回归测试用例 **100%** 通过，**0** 项因本轮改动产生的功能或数据语义回退。
- **SC-008**: 首次登录可用性走查中，**100%** 受测者能在无额外说明下定位验证码输入框并理解须输入四字符验证码（以任务完成率为准）。

## Assumptions

- 前五轮（001～005）功能已上线且行为稳定；本轮在其之上仅做前端体验与视觉层改进。
- 设计风格延续「简洁 + 科技感」；强调色沿用浅色主题蓝、深色主题 NVIDIA 绿；本轮为体系化而非推倒重来。
- 动效常态时长约 150–250ms，克制顺滑、非炫技；遵守 `prefers-reduced-motion`。
- 四象限采用艾森豪威尔语义标签「立即做 / 计划做 / 授权做 / 减少做」；横轴标注「紧急度」、纵轴标注「重要度」，原点 (5,5)，与第四、五轮坐标定义一致。
- 重要度/紧急度可视化采用颜色梯度 + 强度条组合，数字作辅助；低值偏冷色/低饱和，高值偏暖色/高饱和，与现有主题色板协调；具体组件形态由 plan 敲定。
- 分类色带颜色来源于既有分类展示逻辑；若某分类无配置色，使用中性与全站边框色一致的分隔样式。
- 空状态使用图标级视觉即可，不必定制插画；引导文案与主操作按钮是重点。
- 成功反馈采用轻量 toast，自动消失、不打断操作；多条连续成功可合并或替换显示，不要求持久通知中心。
- 若实现中发现必须动后端或数据模型才能实现某条视觉需求，须在 plan 中单列并单独确认，不得擅自改范围。
- 加载骨架适用于日程列表与卡片网格的主要数据获取场景；极短加载允许一闪而过。
- 登录页备案占位区域（005）保留；本轮在优化构图时与之协调而非移除。
- 触摸设备拖拽删除的降级策略（005：可不实现触摸拖拽）保持不变；本轮放置反馈在支持拖拽的指针设备上为必达。
- 不新增坐标图点击导航、不新增 AI 写日程、不引入多用户或后端变更，符合宪法 v1.3.1 范围约束。

## Dependencies

- **001～005 既有功能**：搜索、编辑、视图导航、拖拽删除、垃圾箱、优先级坐标、时间模型、鉴权等行为须保持不变，作为回归基线。
- **宪法原则 IV（日程卡片）**：重要度/紧急度刻度、生命周期与视图过滤语义不得在本轮被重新解释。
- **宪法原则 V（多设备一致）**：视觉与动效升级须在响应式布局与明暗主题各设备上一致可用。
