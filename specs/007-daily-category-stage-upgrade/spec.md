# Feature Specification: 日报、分类管理、日程阶段与体验升级

**Feature Branch**: `007-daily-category-stage-upgrade`

**Created**: 2026-07-20

**Status**: Draft

**Input**: User description: "这是 Watson 的第七轮迭代「日报、分类管理、日程阶段与体验升级」。在 001～006 之上新增每日 GRAI 日报、可自定义分类、日程处理阶段、日视图时间分区与内嵌布局，并完成交互、美术升级和缺陷修复。日报、分类增删、日程阶段触及持久化；其余为呈现与交互增强。"

## Clarifications

### Session 2026-07-20

- Q: 日报如何归属和保存？ → A: 以日期为唯一键，每日一份独立于卡片的三段文本记录并保留时间戳；失焦保存，仅日视图展示。
- Q: 窄屏下三栏日报如何呈现？ → A: 按 Goal、Result、Analysis & Insight 顺序堆叠为三行。
- Q: 「无」分类、既有默认分类和空分类如何处理？ → A: 幂等保证固定「无」分类存在；删分类后卡片改归「无」；「个人」存在时新卡片仍默认「个人」；既有空分类保持现状。
- Q: 日程阶段在哪里展示和筛选？ → A: 卡片上使用带色文字徽章或角标；仅“全部”视图新增阶段筛选器。
- Q: 日视图时间分区与布局规则是什么？ → A: 按结束当天、跨越当天、开始当天依次归入三个互斥章节；右侧坐标图不变，左上独立滚动且不推动左下日报。
- Q: 新优先级色条与旧输入方式是什么关系？ → A: 编辑态完全替换旧竖向数字列，吸附 0～10 整数；只读强度条及坐标图定位逻辑不变。
- Q: 全部视图哪些卡片显示过期泛红？ → A: 仅已安排、结束时间已过、仍活跃且未完成的卡片泛红。
- Q: 单卡多种视觉标识如何避免冲突？ → A: 分类色带走左缘、阶段徽章走角标、悬停窄条走顶边，须与完成框及过期底色统筹且不重叠。
- Q: 本轮动效时长和无障碍边界是什么？ → A: 常态约 150～250ms，且一律尊重系统减少动态效果偏好。
- Q: 既有默认分类「个人」被删除后，新卡片默认归入哪里？ → A: 默认改为「无」，且不自动重建「个人」。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按日记录 GRAI 日报 (Priority: P1)

作为所有者，我希望在日视图中按 Goal、Result、Analysis & Insight 三栏记录当天的目标、结果与分析复盘，并在浏览不同日期时看到对应日报，以便让琐碎事件沉淀为按日可回顾的记录。

**Why this priority**: 日报是本轮新增的核心用户价值，也是独立于日程卡片的新持久化内容。

**Independent Test**: 在日视图选择某一天，分别编辑三栏、离开编辑状态并切换日期，再返回原日期，确认内容按天保存、以 Markdown 形式展示且不会出现在其他视图。

**Acceptance Scenarios**:

1. **Given** 所有者位于某日的日视图且当天没有日报，**When** 点击任一栏并输入纯文本，**Then** 该栏进入编辑状态，其他栏保持常态。
2. **Given** 所有者正在编辑日报栏，**When** 该栏失去焦点，**Then** 内容自动保存并按 Markdown 渲染展示；再次点击该栏可继续编辑原始文本。
3. **Given** 两个日期分别保存了不同日报，**When** 所有者通过翻页或锚定日期在两日之间切换，**Then** 每个日期只显示其自身日报，内容互不覆盖。
4. **Given** 某日已保存日报，**When** 所有者进入周、月、全部或垃圾箱视图，**Then** 日报区与日报内容均不出现。
5. **Given** 自动保存失败，**When** 所有者离开编辑状态，**Then** 系统明确提示未保存，并保留当前输入以便重试，不能以已保存状态误导所有者。

### User Story 2 - 自定义日程分类 (Priority: P1)

作为所有者，我希望在创建或编辑卡片的分类选择控件旁直接新增和删除分类，以便分类体系能随我的实际工作方式变化，而不需要进入独立管理页面。

**Why this priority**: 分类直接影响所有卡片的组织方式；新增、删除及删除后的归属迁移必须保持数据一致。

**Independent Test**: 从卡片表单新增一个唯一分类并用于卡片，再删除该分类，确认其卡片全部归入不可删除的「无」分类，且原有新建卡片默认分类行为未改变。

**Acceptance Scenarios**:

1. **Given** 所有者打开创建或编辑卡片表单，**When** 在分类控件旁新增一个未被使用的分类名称，**Then** 新分类立即可供选择，且无需离开当前表单。
2. **Given** 已存在同名分类，**When** 所有者尝试再次新增，**Then** 系统拒绝创建并明确提示分类不可重名。
3. **Given** 某自定义分类关联一张或多张卡片，**When** 所有者确认删除该分类，**Then** 分类被移除，所有原属该分类的卡片自动归入「无」。
4. **Given** 系统分类「无」，**When** 所有者查看或操作分类选择控件，**Then** 「无」始终存在且不能被删除。
5. **Given** 「个人」分类仍存在，**When** 所有者新建卡片且未主动修改分类，**Then** 默认分类仍为「个人」；**Given** 「个人」已被删除，**When** 再新建卡片，**Then** 默认分类为「无」，系统不自动重建「个人」。

### User Story 3 - 标记与筛选日程处理阶段 (Priority: P1)

作为所有者，我希望为卡片选择「未开始 / 正在处理 / 等待收尾」之一，并在“全部”视图按该阶段筛选，以便区分我当前是否正在处理某件事，而不把它与日程时间安排混为一谈。

**Why this priority**: 阶段是日程卡片的新核心属性，需要在历史数据、创建编辑、卡片扫视和跨视图筛选中保持一致。

**Independent Test**: 创建三张不同阶段卡片，在各视图检查视觉标识，并在“全部”视图逐项筛选；再检查历史卡片与新建卡片默认均为「未开始」，且修改阶段不会改变起止时间或安排状态。

**Acceptance Scenarios**:

1. **Given** 所有者创建新卡片且未调整阶段，**When** 保存卡片，**Then** 阶段为「未开始」。
2. **Given** 本轮上线前已存在的卡片，**When** 所有者查看或编辑它，**Then** 其阶段视为「未开始」。
3. **Given** 所有者编辑卡片，**When** 在三种阶段间切换并保存，**Then** 新阶段被持久保留，卡片的起止时间与已安排/未安排状态均不因此变化。
4. **Given** “全部”视图存在不同阶段的卡片，**When** 所有者选择一个日程阶段筛选条件，**Then** 只显示符合该阶段且同时满足其他既有筛选条件的卡片。
5. **Given** 卡片处于任一阶段，**When** 所有者在卡片上查看阶段标识，**Then** 三态通过带色文字徽章或角标清晰区分，并在明暗主题下均可辨认。

### User Story 4 - 按时间关系浏览日视图 (Priority: P1)

作为所有者，我希望日视图左侧把当天相关卡片依次分为「今天截止」「正在进行」「今天开始」三个章节，以便快速理解每件事与当天的时间关系，且任何卡片不遗漏、不重复。

**Why this priority**: 这是日视图的核心信息架构变更，直接决定每日浏览效率与时间语义正确性。

**Independent Test**: 准备覆盖当天开始、当天结束、跨越全天及同日开始结束的卡片，确认每张相关卡片恰好出现一次、落入正确章节，其他日期及未安排卡片不出现。

**Acceptance Scenarios**:

1. **Given** 已安排卡片的结束时间落在锚定日期内，**When** 打开该日日视图，**Then** 卡片出现在「今天截止」。
2. **Given** 已安排卡片开始早于锚定日期且结束晚于锚定日期，**When** 打开该日日视图，**Then** 卡片出现在「正在进行」。
3. **Given** 已安排卡片的开始时间落在锚定日期内且结束时间不在当天，**When** 打开该日日视图，**Then** 卡片出现在「今天开始」。
4. **Given** 卡片在锚定日期内开始并结束，**When** 打开该日日视图，**Then** 它只出现在「今天截止」，不在「今天开始」重复出现。
5. **Given** 未安排卡片或时间区间与锚定日期无交集，**When** 打开该日日视图，**Then** 该卡片不显示；未安排卡片仍只进入全部视图。

---

### User Story 5 - 独立使用日视图三大区域 (Priority: P2)

作为所有者，我希望日视图右侧坐标图保持常驻，左侧上部浏览时间章节、下部编辑日报；卡片很多时只滚动左上卡片区，以便浏览日程时不推走日报或坐标图。

**Why this priority**: 新日报与时间章节必须在有限空间中共存，区域独立性决定日视图是否可持续使用。

**Independent Test**: 在当日放入足以溢出的卡片并填写日报，滚动左上区域，确认日报与右侧坐标图位置不被推动；三个区域的既有交互均可单独完成。

**Acceptance Scenarios**:

1. **Given** 常规宽度的日视图，**When** 所有者查看页面，**Then** 右侧为既有常驻二维优先级坐标图，左侧上大下小，上部为三个卡片章节，下部为三栏日报。
2. **Given** 左上卡片内容超过可见高度，**When** 所有者上下滚动查看更多卡片，**Then** 只有左上卡片区滚动，左下日报与右侧坐标图不随之移动。
3. **Given** 卡片区可继续滚动，**When** 所有者接近其上边缘或下边缘，**Then** 相应边缘出现轻量渐隐提示；到达边界后不再误示该方向仍有内容。
4. **Given** 较窄的受支持屏幕，**When** 布局为保持可用性而自适应，**Then** 时间章节、日报与坐标图仍可分别访问，且各自滚动或编辑不会造成内容不可达。

---

### User Story 6 - 更高效地创建与编辑卡片 (Priority: P2)

作为所有者，我希望通过可拖动横向色条设置重要度和紧急度，并在不增大弹层的情况下获得更合理的字段布局和更大的描述区，以便更快完成卡片录入。

**Why this priority**: 创建和编辑是高频路径；输入方式与空间排布直接影响操作效率。

**Independent Test**: 打开创建和详情编辑弹层，拖动两个优先级色条到 0、5、10，检查整数吸附、颜色强弱和数值气泡；同时核对时间、分类/阶段及描述区布局，确认只读展示不变。

**Acceptance Scenarios**:

1. **Given** 所有者创建或编辑卡片，**When** 拖动重要度或紧急度横向色条，**Then** 数值仅落在 0～10 的整数上，颜色随数值由淡到浓，并显示跟随当前位置的当前数值气泡。
2. **Given** 所有者将色条拖至两端或任意中间位置，**When** 松开操作，**Then** 0、10 及所有中间整数均可准确选择。
3. **Given** 所有者只读查看卡片，**When** 查看重要度和紧急度，**Then** 继续使用第六轮既有可视化展示，不出现可编辑色条。
4. **Given** 创建或详情表单，**When** 查看字段排布，**Then** 不再显示「时间（可选）」行标签；开始与结束时间同排，重要与紧急程度同排，分类与日程阶段同排，描述输入区获得更多高度，弹层整体大小不变。
5. **Given** 所有者创建、打开或关闭卡片详情，**When** 弹层进入或离开，**Then** 具有流畅且不阻塞操作的出现/消失过渡，而非瞬间跳变。
6. **Given** 创建或编辑表单已使用横向优先级色条，**When** 所有者设置重要度或紧急度，**Then** 旧竖向数字列不再同时出现，且卡片在坐标图中的定位结果不变。

### User Story 7 - 获得一致、克制的交互反馈 (Priority: P2)

作为所有者，我希望导航、卡片、坐标图、主题、空状态、日报与拖拽删除都有清晰而克制的反馈，以便能感知当前焦点和操作结果，同时在减少动态效果模式下不受干扰。

**Why this priority**: 这些反馈共同提升日常使用的可理解性和完成度，但不改变业务数据与操作语义。

**Independent Test**: 逐项触发视图切换、列表刷新、卡片悬停、坐标聚合圆悬停、主题切换、日报编辑、删除确认和拖拽进垃圾箱；再开启系统「减少动态效果」重复测试。

**Acceptance Scenarios**:

1. **Given** 所有者切换日/周/月/全部视图，**When** 选中项变化，**Then** 选中高亮平滑滑动至目标项；卡片列表刷新时以轻微交错淡入出现。
2. **Given** 所有者在日视图或全部视图悬停卡片，**When** 指针进入或离开，**Then** 卡片顶部的横向窄装饰条随之出现或消失，不承载操作且不遮挡内容。
3. **Given** 坐标图存在聚合圆，**When** 所有者悬停它，**Then** 圆放大并高亮；能够明确对应左侧卡片时，对应卡片同步高亮。
4. **Given** 所有者切换明暗主题或进入日报某栏编辑，**When** 状态变化，**Then** 配色柔和过渡，当前日报栏轻微强调且其他栏保持常态。
5. **Given** 任一视图为空，**When** 所有者停留查看，**Then** 空状态图标具有极轻的呼吸反馈，不影响文案阅读。
6. **Given** 所有者触发删除或永久删除确认，**When** 确认框出现，**Then** 危险操作的配色与层级被强化，取消操作保持可见但视觉弱于危险确认。
7. **Given** 所有者拖卡片进入垃圾箱，**When** 进入放置目标并成功松手，**Then** 可见拖影、目标高亮与成功接收反馈，删除业务语义保持不变。
8. **Given** 系统启用「减少动态效果」，**When** 触发本特性的任一非必要动效，**Then** 动效被取消或显著简化，所有信息、状态与操作结果仍清晰可用。

### User Story 8 - 识别过期卡片并正常使用导航 (Priority: P2)

作为所有者，我希望在全部视图一眼识别已过期但仍活跃的已安排卡片，并能完整看到悬停上浮的日期翻页按钮，以免遗漏待处理事项或受到显示缺陷干扰。

**Why this priority**: 两项均修复会影响判断或操作的现有缺陷，范围明确且可独立验证。

**Independent Test**: 在全部视图准备已过期、未过期和未安排卡片，核对仅目标卡片背景泛红；再在日/周/月视图悬停所有「上一 / 本 / 下一」按钮，确认上浮后完整可见。

**Acceptance Scenarios**:

1. **Given** 已安排卡片仍处于活跃态且结束时间早于当前时刻，**When** 所有者在全部视图查看它，**Then** 卡片背景泛红以提示过期。
2. **Given** 同一张过期卡片出现在日、周或月视图，**When** 所有者查看它，**Then** 不应用全部视图专属的过期背景。
3. **Given** 未安排卡片没有结束时间，**When** 所有者在全部视图查看它，**Then** 不因存在时长或创建较早而被标为过期。
4. **Given** 所有者位于日、周或月视图，**When** 悬停「上一 / 本 / 下一」任一日期导航按钮，**Then** 按钮上浮动画完整可见，上部不被容器裁切。

---

### User Story 9 - 保持既有能力无损 (Priority: P1)

作为所有者，我希望升级后仍能按原有方式登录、管理卡片生命周期、使用各视图、搜索筛选、拖拽删除和使用纯文本 AI 对话，以便新能力不会破坏 001～006 已上线功能。

**Why this priority**: 本轮横跨数据与多个高频界面，回归无损是交付底线。

**Independent Test**: 完整执行 001～006 的已验证回归用例，并额外验证新增日报、分类和阶段不会绕过鉴权、改变时间合法性或让 AI 操作日程。

**Acceptance Scenarios**:

1. **Given** 未授权访问者，**When** 尝试读取或修改日报、分类或卡片阶段，**Then** 与既有日程数据一样无法访问。
2. **Given** 所有者使用 AI 对话，**When** 请求 AI 操作日报、分类或日程，**Then** AI 仍不执行任何日程数据的增删改查或联动。
3. **Given** 所有者完成、删除、恢复或永久删除卡片，**When** 本轮升级已启用，**Then** 核心生命周期语义与第六轮结束时一致。
4. **Given** 001～006 的既有验收场景，**When** 执行全量回归，**Then** 所有场景保持通过。
5. **Given** 同一所有者在两台设备上保持 Watson 前台可见，**When** 设备 A 修改日报、分类或卡片阶段，**Then** 设备 B 在 3 秒内看到更新，无需切换后台或手动刷新。

### Edge Cases

- 日报某栏为空时，失焦保存后保持可再次点击编辑的空状态；空内容不影响另两栏。
- 日报包含标题、列表、链接或其他合法 Markdown 时应正确展示；输入内容不得形成可执行或危害页面的内容。
- 快速切换日期发生在日报尚未完成保存时，系统不得把前一日内容写到后一日；失败或未完成状态须可见。
- 新增分类名称为空、仅为空白或与既有分类重复时不得创建；名称比较沿用现有不可重名规则。
- 删除当前表单中已选分类后，该表单及受影响卡片均应显示「无」，不得保留悬空分类引用。
- 「无」分类即使当前没有卡片也必须存在；任何入口都不得允许重命名或删除它。
- 本轮上线前分类为空的卡片保持既有空分类语义，不自动并入「无」；「无」只承接被删除分类的卡片。
- 历史卡片缺少阶段信息时一律按「未开始」呈现和筛选；不得因此变成无效卡片。
- “全部”视图多个筛选条件同时启用时，日程阶段筛选与既有条件共同生效，而不是覆盖其他条件。
- 卡片时间恰好落在一天起止边界时，按锚定日期所采用的既有日历时区判定，且仍须不漏不重。
- 某时间章节为空时，其余章节顺序与归类不变；空章节不应造成整个卡片区被误判为空。
- 大量卡片导致滚动时，日报和坐标图保持可操作；渐隐提示不得遮挡卡片操作。
- 优先级色条在键盘、触摸或精细指针输入下均须可选择全部 11 个整数值，不能只依赖鼠标拖动。
- 坐标聚合圆对应多张卡片时，只联动能够明确表达的对应集合，不得错误高亮无关卡片。
- 全部视图过期判断以当前时刻与结束时间比较；已完成或已删除卡片不因本规则重新进入活跃列表。
- 单卡同时具有分类左缘色带、阶段徽章、完成框、悬停顶部窄条及过期红底时，各标识不得相互遮挡或削弱操作可用性。
- 所有新增动效与反馈均须在明暗主题和「减少动态效果」偏好下单独验证。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001（触及数据）**: 系统 MUST 以日历日期为唯一归属保存每日一份独立 GRAI 日报，包含 Goal、Result、Analysis & Insight 三个可独立编辑的纯文本内容栏及创建、更新时间信息；日报与日程卡片之间 MUST NOT 建立归属或生命周期依赖。
- **FR-002（触及数据）**: GRAI 日报 MUST 只在日视图显示，并随日视图的锚定日期和翻页结果切换；周、月、全部与垃圾箱视图 MUST NOT 显示日报。
- **FR-003（触及数据）**: 日报栏 MUST 在点击后进入纯文本编辑、失焦后自动保存并按 Markdown 展示，再次点击后恢复编辑；保存失败 MUST 明确告知且保留未保存输入。
- **FR-004（触及数据）**: 所有者 MUST 能从创建/编辑卡片的分类选择控件旁新增和删除分类，MUST NOT 为此新增独立分类管理页。
- **FR-005（触及数据）**: 分类名称 MUST 沿用既有不可重名规则；空名称或仅含空白的名称 MUST NOT 被创建。
- **FR-006（触及数据）**: 系统 MUST 始终保留名为「无」的兜底分类，且 MUST NOT 允许删除或重命名它。
- **FR-007（触及数据）**: 删除分类时，系统 MUST 将所有原属于该分类的卡片归入「无」；「个人」存在时新建卡片 MUST 继续默认使用「个人」，若「个人」已被删除则 MUST 默认使用「无」且不得自动重建「个人」；本轮上线前分类为空的卡片 MUST 保持原状，不自动并入「无」。
- **FR-008（触及数据）**: 每张日程卡片 MUST 具有独立于时间安排的「日程所处阶段」，且值严格限定为「未开始 / 正在处理 / 等待收尾」三者之一。
- **FR-009（触及数据）**: 新卡片阶段 MUST 默认为「未开始」；本轮上线前的历史卡片 MUST 一律视为「未开始」。
- **FR-010（触及数据）**: 所有者 MUST 能在创建与编辑卡片时选择阶段；修改阶段 MUST NOT 自动改变卡片的起止时间、已安排/未安排状态或生命周期。
- **FR-011（呈现增强）**: 卡片 MUST 以带色文字徽章或角标清晰标示阶段，三态在明暗主题下均须可辨，不得仅凭颜色传达含义。
- **FR-012（呈现增强）**: “全部”视图 MUST 提供日程阶段筛选器，并与该视图的既有筛选条件共同生效；日、周、月视图 MUST NOT 因本轮新增该筛选器。
- **FR-013（呈现增强）**: 日视图 MUST 将与锚定日期相关的已安排卡片按「今天截止 → 正在进行 → 今天开始」的固定顺序分区展示。
- **FR-014（呈现增强）**: 分区判据 MUST 为：结束时间落在当天归「今天截止」；开始早于当天且结束晚于当天归「正在进行」；开始时间落在当天归「今天开始」；同日开始并结束时优先归「今天截止」，每张卡片 MUST 恰好出现一次。
- **FR-015（呈现增强）**: 日视图 MUST 排除与锚定日期无关及未安排卡片；未安排卡片继续只进入全部视图。
- **FR-016（呈现增强）**: 常规宽度下日视图 MUST 保留右侧既有常驻二维优先级坐标图；左侧 MUST 上大下小，上部为卡片三区段，下部为一排三栏 GRAI 日报；窄屏下日报 MUST 按 Goal、Result、Analysis & Insight 顺序堆叠为三行，并保持时间章节与坐标图均可访问。
- **FR-017（呈现增强）**: 当卡片溢出时，MUST 仅允许左侧上部卡片区独立滚动，不得推动左下日报或右侧坐标图；可继续滚动的上下边缘 MUST 提供不遮挡操作的渐隐提示。
- **FR-018（呈现增强）**: 顶栏空置品牌位 MUST 使用符合日程语义的简洁线性标识，标题文字 MUST 精简为「Watson」。
- **FR-019（呈现增强）**: 日视图与全部视图卡片在悬停时，顶部 MUST 出现横向窄条装饰反馈，移开即消失，且 MUST NOT 承载操作或遮挡内容。
- **FR-020（呈现增强）**: 创建与编辑卡片时，重要度和紧急度 MUST 使用可直接拖动的横向色条完整替换旧竖向数字列，二者不得并存；色条须选择 0～10 离散整数、吸附到整数、以由淡到浓表达强弱，并在拖动时显示当前值气泡；只读强度条展示与坐标图定位逻辑保持不变。
- **FR-021（呈现增强）**: 卡片创建/详情表单在整体大小不变的前提下，MUST 移除「时间（可选）」行标签，将开始/结束时间同排、重要/紧急程度同排、分类/日程阶段同排，并增大描述输入区高度。
- **FR-022（呈现增强）**: 创建卡片及卡片详情的打开与关闭 MUST 具有流畅的出现/消失过渡，不得阻塞操作。
- **FR-023（呈现增强）**: 视图选中高亮滑动、列表交错淡入、坐标聚合圆悬停、明暗主题切换、空状态呼吸、日报编辑强调、删除确认、拖拽进垃圾箱等反馈 MUST 符合各用户场景，常态过渡时长 SHOULD 约为 150～250ms，并 MUST NOT 改变原业务结果。
- **FR-024（呈现增强）**: 坐标图聚合圆悬停时 MUST 放大并高亮；在映射关系明确时 SHOULD 与左侧对应卡片联动高亮，不得错误关联无关卡片。
- **FR-025（呈现增强）**: 删除与永久删除确认框 MUST 强化危险语义并弱化取消操作的视觉层级，但取消仍须清晰可发现且可正常使用。
- **FR-026（呈现增强）**: 拖拽卡片进入垃圾箱时 MUST 提供拖影、放置目标高亮与成功接收反馈，删除、恢复与永久删除语义保持不变。
- **FR-027（呈现增强）**: 所有非必要动效 MUST 尊重系统「减少动态效果」偏好；降级后信息、状态和操作结果 MUST 保持完整。
- **FR-028（缺陷修复）**: “全部”视图 MUST 仅对结束时间早于当前时刻且仍活跃、未完成的已安排卡片显示泛红背景；未安排、已完成、已删除卡片及日/周/月视图 MUST NOT 应用该提示。
- **FR-029（缺陷修复）**: 日、周、月视图的「上一 / 本 / 下一」日期导航按钮悬停上浮时 MUST 完整可见，不得被容器边界裁切。
- **FR-030（范围约束）**: 新增持久化范围 MUST 仅限 GRAI 日报、分类增删及迁移归属、日程阶段；其他条目 MUST 保持为呈现与交互增强。
- **FR-031（范围约束）**: 系统 MUST 继续满足仅标题必填、标题不可重名、已安排卡片起止时间皆有且结束不早于开始、未安排卡片起止皆空且只进入全部视图等既有规则。
- **FR-032（范围约束）**: 本轮 MUST NOT 改变单用户鉴权、AI 不操作日程、卡片完成/删除/恢复/永久删除及垃圾箱等既有功能语义。
- **FR-033（回归）**: 交付前 MUST 回归验证 001～006 的已验收功能，包括坐标图、日期翻页、筛选、搜索、创建编辑、拖拽删除、垃圾箱、明暗主题与响应式使用，确认无功能回退。
- **FR-034（呈现增强）**: 单张卡片同时呈现多种标识时，分类色带 MUST 位于左缘、阶段徽章 MUST 位于不遮挡内容的角标区域、悬停窄条 MUST 位于顶边，并与完成框及“全部”视图过期红底统筹排布，不得重叠、遮挡或造成操作歧义。
- **FR-035（多设备一致）**: 当多个已登录设备保持页面前台可见时，一台设备对日报、分类或卡片阶段的修改 MUST 在其他设备 3 秒内可见；页面从后台恢复可见时 MUST 立即发起刷新，且不得依赖 AI 触发。

### Key Entities *(include if feature involves data)*

- **每日 GRAI 日报**：以日历日期唯一标识的独立复盘记录；包含 Goal、Result、Analysis & Insight 三栏纯文本内容及创建、更新时间。不同日期相互独立，仅在日视图使用，与日程卡片无归属关系。
- **分类**：所有者可自定义的卡片归类项；名称不可重复。系统幂等保证不可删除、不可重命名的「无」分类存在，作为已删除分类的卡片归属去向；新建卡片在「个人」存在时默认「个人」，否则默认「无」且不重建「个人」；既有空分类卡片保持原状。
- **日程阶段**：日程卡片的独立处理状态，取值为未开始、正在处理、等待收尾；不表达或推导时间安排。
- **日程卡片**：沿用既有核心实体，新增日程阶段关联；分类、时间、优先级和生命周期等原有语义继续有效。
- **日视图时间章节**：基于卡片时间区间与锚定日期的关系形成的「今天截止 / 正在进行 / 今天开始」展示分组，不是新增持久化实体。

## Success Criteria *(mandatory)*

- **SC-002**: 对至少 **20 张**跨多个日期且覆盖全部边界类型的已安排卡片进行日视图归类时，相关卡片分区正确率达到 **100%**，重复和遗漏均为 **0**。
- **SC-003**: 新增、选用和删除一个自定义分类的完整任务可在 **60 秒内**完成；删除后受影响卡片归入「无」的正确率为 **100%**，悬空分类引用为 **0**。
- **SC-004**: 新卡片与历史卡片默认阶段正确率为 **100%**；在“全部”视图中，按三种阶段筛选的结果准确率为 **100%**，日/周/月视图新增阶段筛选器的数量为 **0**。
- **SC-005**: 对 0～10 共 **11 个**优先级值逐一输入时，重要度与紧急度色条均可准确选中每个整数，非整数持久值为 **0**。
- **SC-006**: 在卡片数量足以溢出的日视图中进行滚动时，日报与坐标图位置受卡片滚动影响的次数为 **0**，三个区域的关键操作完成率为 **100%**。
- **SC-007**: 在浅色、深色以及系统启用「减少动态效果」三种环境下，本轮新增或修改的关键交互任务完成率均为 **100%**，且无信息只能依赖动画或颜色辨识。
- **SC-008**: 全部视图中过期活跃已安排卡片的提示准确率为 **100%**，未安排或非全部视图卡片的误标率为 **0%**。
- **SC-009**: 日、周、月三种视图中全部日期导航按钮在悬停上浮后均 **100%** 完整可见，无任何边缘裁切。
- **SC-010**: 001～006 已验证回归用例 **100%** 通过；因本轮改动产生的鉴权、数据语义、生命周期、视图、搜索、筛选、坐标图或拖拽回退为 **0**。
- **SC-011**: 由不超过 **5 名**目标用户或评审者完成日报、分类管理、阶段筛选和日视图浏览四项首次使用任务时，至少 **90%** 的任务无需额外说明即可成功完成。
- **SC-012**: 在两台同时保持前台可见的已登录设备间，日报、分类和卡片阶段三类修改的可见延迟均不超过 **3 秒**；任一设备恢复可见后首次刷新立即触发。

## Assumptions

- 本特性沿用单用户所有者模型与现有受保护会话；日报、分类和阶段数据与日程数据受到同等访问保护。
- 日报日期和日视图分区均沿用现有日/周/月视图的日历时区与锚定日期定义，不另设日报时区。
- 每个日期只有一份日报，每份固定包含三栏并保留创建、更新时间；本轮不提供日报搜索、跨日汇总、导出、历史版本或其他视图入口。
- Markdown 只用于日报失焦后的安全展示；编辑时始终是原始纯文本。本轮不扩展为富文本编辑器。
- 分类管理只在分类选择控件旁提供；本轮不新增分类排序、合并、批量改名或独立管理页面。
- 删除非兜底分类属于需要明确确认的破坏性操作；删除后卡片迁移至「无」不可被解释为删除卡片。
- 新建卡片优先默认「个人」；若「个人」被所有者删除，则默认「无」且不自动重建「个人」。既有空分类卡片不自动迁移。
- 阶段筛选只在“全部”视图中收窄卡片集合，不改变该视图的活跃状态规则或其他筛选条件。
- 日期边界采用半开日历区间理解：当天起点属于当天，下一天起点不属于前一天；实际边界细节在 plan 中与既有日期行为对齐。
- 日报三栏在有足够宽度时保持一排三列；窄屏按 Goal、Result、Analysis & Insight 顺序堆叠为三行。
- 动效延续第六轮克制、快速的视觉基调，常态过渡约为 150～250ms，并一律支持减少动态效果降级。
- 坐标图与左侧卡片联动仅在对应关系明确时启用；无法可靠对应时保留聚合圆自身高亮即可。
- 本轮不新增多用户、协作、第三方日历同步、AI 日程操作，也不改变现有部署与鉴权方式。

## Dependencies

- **001～006 既有能力**：鉴权、卡片模型、创建编辑、搜索筛选、日/周/月/全部视图、日期导航、优先级坐标图、垃圾箱、拖拽删除、主题与视觉体系均是本轮基线。
- **既有时间规则**：已安排卡片必须同时具有合法起止时间，未安排卡片起止皆空；日视图分区依赖该规则。
- **既有分类默认行为与不可重名规则**：本轮新增管理能力，但不重新定义默认分类和名称相等的判据。
- **多设备一致体验**：新增数据和交互须在所有受支持浏览器设备上访问同一份数据，并保持核心任务可完成。
