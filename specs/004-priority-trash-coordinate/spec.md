# Feature Specification: 优先级量化、垃圾箱与坐标视图

**Feature Branch**: `004-priority-trash-coordinate`

**Created**: 2026-07-15

**Status**: Draft

**Input**: User description: "这是 Watson 的第四轮迭代，命名为「优先级量化、垃圾箱与坐标视图」。在已上线的 001/002/003 之上，重构优先级与时间模型、引入卡片生命周期（完成/删除/恢复的垃圾箱）、新增二维坐标视图，并做一批交互与视觉修正。"

## Clarifications

### Session 2026-07-15

- Q: 历史「截止型」卡片如何迁入新时间模型？ → A: 清空其时间字段，降级为「未安排」（所有者可再手填起始/结束）。
- Q: 详情「恢复」与垃圾箱「恢复」文案冲突？ → A: 详情重置草稿改称「重置」；垃圾箱生命周期操作仍称「恢复」。
- Q: 坐标悬停是否必须列出全部名称？ → A: 列出任务名；过多时可滚动查看全部，或先展示若干条并以「+N」标明其余，不得无法得知被省略数量。
- Q: 垃圾箱内的卡片能否打开详情并编辑？ → A: 可打开只读详情；不可在箱内编辑；改内容须先恢复为活跃。
- Q: 全局标题搜索是否包含垃圾箱中的卡片？ → A: 搜索含垃圾箱；候选标注「已完成/已删除」，点开进入只读详情。
- Q: 取消「时间性质」后全部视图筛选如何调整？ → A: 用「已安排 / 未安排」替换原时间性质及有无时间筛选；保留分类、重要度、紧急度等其余筛选。
- Q: 坐标视图中点击聚合圆如何表现？ → A: 仅悬停展示任务名单；点击圆无额外行为。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 卡片完成、删除与垃圾箱恢复 (Priority: P1)

作为所有者，我希望能把日程标记为「已完成」或「删除」并统一进入垃圾箱，之后可恢复或永久删除，以便清理主视图又不立刻丢掉内容。

**Why this priority**: 本轮引入卡片生命周期的核心价值；完成/删除/恢复/永久删除必须语义一致，是后续快捷完成入口与坐标视图过滤的基础。

**Independent Test**: 创建若干活跃卡片；分别完成与删除；确认它们从日/周/月/全部/坐标视图消失并出现在垃圾箱；恢复后回到常规视图；永久删除后不可再恢复。

**Acceptance Scenarios**:

1. **Given** 所有者查看一活跃日程详情或可完成入口，**When** 标记为「已完成」，**Then** 该卡片立即进入垃圾箱，**不**弹出二次确认；常规视图（日 / 周 / 月 / 全部 / 坐标）中不再出现。
2. **Given** 所有者对一活跃日程执行删除，**When** 确认删除二次确认，**Then** 该卡片进入垃圾箱并从常规视图消失；**When** 取消二次确认，**Then** 卡片仍保持活跃。
3. **Given** 页面右上角原「登出」位置，**When** 所有者查看导航，**Then** 看到垃圾箱图标（无「登出」按钮）；点击后打开垃圾箱视图。
4. **Given** 垃圾箱内有多张卡片，**When** 所有者查看列表，**Then** 呈现方式类似「全部」视图，但按「进入垃圾箱的时间」倒序：最近进箱的在左上，较早的向右向下排列。
5. **Given** 垃圾箱中的已完成卡片与已删除卡片，**When** 所有者辨认，**Then** 已完成卡片带对勾标记，已删除卡片带红色圆形标记。
6. **Given** 垃圾箱中某张卡片，**When** 所有者选择「恢复」，**Then** 卡片回到活跃状态并重新出现在符合其时间规则的常规视图中。
7. **Given** 垃圾箱中某张卡片，**When** 所有者选择「永久删除」并确认二次确认，**Then** 该卡片不可逆消失，垃圾箱与常规视图均不再出现；取消二次确认则保留在垃圾箱。
8. **Given** 卡片已在垃圾箱（无论完成或删除），**When** 所有者查看日 / 周 / 月 / 全部 / 坐标视图，**Then** 该卡片均不出现。
9. **Given** 垃圾箱中某张卡片，**When** 所有者点击打开详情，**Then** 详情以**只读**呈现（可查看字段与时间戳，不可编辑）；详情内不提供「确认」保存路径，完成方框不可用。
10. **Given** 垃圾箱只读详情已打开，**When** 所有者需要修改内容，**Then** 必须先关闭详情并执行「恢复」，再在活跃详情中编辑。
11. **Given** 存在标题匹配的活跃卡片与垃圾箱卡片，**When** 所有者使用全局标题搜索，**Then** 候选同时可包含二者；垃圾箱来源的候选明确标注「已完成」或「已删除」。
12. **Given** 搜索候选为垃圾箱卡片，**When** 所有者点击该候选，**Then** 打开该卡片的只读详情（与垃圾箱内打开一致）。

### User Story 2 - 时间模型：已安排与未安排 (Priority: P2)

作为所有者，我希望日程不再区分「时间性质」，而仅按「是否填写了起始时间」分为已安排与未安排，以便更自由地记录待办或区间安排。

**Why this priority**: 取消第三轮的「时间性质」强制规则，是创建/编辑与多视图过滤的规则底座；未安排只进全部视图直接改变日历行为。

**Independent Test**: 创建仅标题的卡片（未安排）确认只在全部可见；填写起始时间后出现在日/周/月；可选填结束时间后按区间展示；详情与创建表单中不再出现「时间性质」选项。

**Acceptance Scenarios**:

1. **Given** 所有者手动创建或编辑卡片，**When** 填写字段，**Then** 界面上**不存在**「时间性质」（持续型 / 截止型）选项。
2. **Given** 所有者未填写任何时间字段（含起始时间），**When** 保存成功，**Then** 该卡片为「未安排」；起始时间不会被系统代填。
3. **Given** 「未安排」卡片，**When** 查看日 / 周 / 月视图，**Then** 不出现；**When** 查看全部视图，**Then** 出现。
4. **Given** 所有者主动填写了起始时间，**When** 保存，**Then** 该卡片为「已安排」，并按其起始时间（及可选结束时间）进入相应日 / 周 / 月视图。
5. **Given** 已安排卡片只填了起始时间、未填结束时间，**When** 在日历视图展示，**Then** 按单一起始时刻/日期处理（非强制区间）。
6. **Given** 已安排卡片同时填了起始与结束时间，**When** 展示，**Then** 视为一个时间区间。
7. **Given** 创建或保存时标题为空或与其他**活跃**日程重名，**When** 提交，**Then** 拒绝并提示；仅标题必填规则仍然成立。
8. **Given** 所有者在全部视图使用筛选，**When** 查看时间相关筛选项，**Then** 原「时间性质」「有无时间」已被「已安排 / 未安排」取代；分类、重要度、紧急度等其余筛选仍可用。

### User Story 3 - 重要度与紧急度 0~10 量化 (Priority: P3)

作为所有者，我希望重要程度与紧急程度用 0~10 整数表示，并通过竖向数字条点选，以便更精细地表达优先级并为坐标视图提供刻度。

**Why this priority**: 坐标视图与排序/展示依赖数值刻度；旧三档数据需可理解地迁移。

**Independent Test**: 打开创建或详情，点击重要度/紧急度，从竖向 0~10 条点选；确认新旧数据映射后数值落在 0~10；坐标视图按新数值落点。

**Acceptance Scenarios**:

1. **Given** 所有者编辑重要程度或紧急程度，**When** 点击该属性，**Then** 竖向拉开一列整数（最下 0、最上 10），点选某一数字即设定该值（0 与 10 均可选）。
2. **Given** 历史卡片仍存「高 / 中 / 低」档位，**When** 产品升级后首次加载，**Then** 系统将其合理转换为 0~10 整数（见 Assumptions 映射），所有者可随后再改。
3. **Given** 新建卡片未显式设定重要度或紧急度，**When** 保存，**Then** 采用约定默认值（见 Assumptions），仍落在 0~10。

### User Story 4 - 详情即时编辑与放弃/确认 (Priority: P4)

作为所有者，我希望打开卡片详情后即可直接改各字段，用「重置」撤销本次修改、「确认」才保存关闭，点外部则放弃，以便少点一步编辑并避免多余二次确认（「重置」勿与垃圾箱「恢复」混淆）。

**Why this priority**: 改变第三轮「先编辑再改」的主写路径，与删除精简文案、创建确认体验同属交互一致性。

**Independent Test**: 打开详情直接改标题，点面板外放弃后重新打开仍是原值；再改后点「重置」字段回到打开时原值且详情不关；点「确认」保存并关闭；空标题或重名时就地报错不关不存。

**Acceptance Scenarios**:

1. **Given** 所有者打开任意活跃卡片详情，**When** 详情出现，**Then** 各属性可立即编辑，无需先点「编辑」。
2. **Given** 详情刚打开且尚未修改任何字段，**When** 查看右下角，**Then** 「重置」不可用；「确认」可用（或按 Assumptions：确认在无修改时等同关闭且不写变更）。
3. **Given** 本次打开后已修改至少一个字段，**When** 「重置」变为可用并被点击，**Then** 所有字段重置为**本次打开详情时**的原值，详情保持打开。
4. **Given** 已修改字段且合法，**When** 点击「确认」，**Then** 保存修改并关闭详情；全程**不**弹出二次确认。
5. **Given** 详情打开期间有未保存修改，**When** 点击详情面板以外区域，**Then** 放弃本次修改并关闭详情（等同取消），不写入变更。
6. **Given** 保存时标题为空，或与其他活跃日程重名，**When** 点击「确认」，**Then** 就地提示错误，详情不关闭、不保存。
7. **Given** 详情内删除入口，**When** 查看文案，**Then** 为「删除」（非「删除该日程」）；二次确认框宽度较第三轮明显收窄。

### User Story 5 - 快捷完成入口 (Priority: P5)

作为所有者，我希望在详情右上角以及日视图、全部视图卡片右侧，用方框一点即可完成日程，以便不打开复杂流程也能快速归档。

**Why this priority**: 完成路径日常高频；必须与 P1 垃圾箱语义一致。

**Independent Test**: 分别从详情方框、日视图卡片右侧方框、全部视图卡片右侧方框完成同一类操作；确认均进入垃圾箱且标记为已完成、无二次确认。

**Acceptance Scenarios**:

1. **Given** 活跃卡片详情已打开，**When** 点击右上角完成方框，**Then** 出现对勾，该日程视为已完成并进入垃圾箱（无二次确认）。
2. **Given** 日视图或全部视图中的活跃卡片，**When** 点击该卡片右侧完成方框，**Then** 语义与详情入口一致：完成并进垃圾箱。
3. **Given** 周视图或月视图，**When** 查看卡片，**Then** 不强制提供卡片右侧完成方框（本轮范围仅日视图与全部视图 + 详情）。

### User Story 6 - 二维坐标视图 (Priority: P6)

作为所有者，我希望在日视图与全部视图打开以重要×紧急为轴的坐标视图，聚合同坐标任务，以便一眼看到优先级分布。

**Why this priority**: 本轮新增的空间化分析视图；依赖 P3 数值刻度与 P1「垃圾箱卡片不入常规视图」。

**Independent Test**: 在日视图与全部视图分别点「坐标视图」；确认以 (紧急度, 重要度) 落点、原点在 5/5、同点聚合圆随数量变大、悬停列出任务名；垃圾箱卡片不出现。

**Acceptance Scenarios**:

1. **Given** 所有者处于日视图或全部视图，**When** 查看界面，**Then** 各有一个「坐标视图」入口按钮。
2. **Given** 点击「坐标视图」，**When** 视图打开，**Then** 在页面中心展示二维坐标系：以重要程度 5、紧急程度 5 为原点；横轴为紧急程度、纵轴为重要程度；右上方向表示更重要且更紧急。
3. **Given** 当前所在视图（日或全部）中有活跃卡片，**When** 坐标视图渲染，**Then** 每张卡片按其（紧急度, 重要度）落点；已完成/已删除（垃圾箱）卡片不出现。
4. **Given** 同一坐标存在多张卡片，**When** 渲染，**Then** 聚合为一个圆，该点任务越多圆越大。
5. **Given** 鼠标悬停某个圆，**When** 弹出信息框，**Then** 列出该圆任务名称；名称过多时可滚动查看全部，或先展示若干条并以「+N」标明其余数量。
5b. **Given** 鼠标点击某个圆，**When** 点击发生，**Then** 无额外行为（不打开详情、不固定列表、不关闭坐标视图）；任务名单仍仅由悬停呈现。
6. **Given** 坐标视图基于日视图打开，**When** 展示，**Then** 仅包含该日视图当前可见范围内的活跃卡片；基于全部视图打开则包含全部视图当前活跃集合。

### User Story 7 - 导航与布局体验修正 (Priority: P7)

作为所有者，我希望默认隐藏 AI、精简顶栏控件文案、日/全部按创建时间铺排、并改善周/月拥挤与越界问题，以便日常浏览更干净、可扫读。

**Why this priority**: 多项体验债修复，单点改动可独立验收，不阻塞 P1–P6 主能力，但同属本轮交付范围。

**Independent Test**: 逐项对照验收场景检查 AI 默认态与按钮配色、主题按钮文案、创建确认、日/全部排序与缩放、跨天展示规则、页边距与周/月拥挤。

**Acceptance Scenarios**:

1. **Given** 所有者新打开或刷新应用，**When** 主界面加载完成，**Then** 右侧 AI 助手默认隐藏。
2. **Given** AI 显隐切换按钮，**When** 查看文案，**Then** 统一为「AI」；隐藏时按钮为白色（浅色主题）/对应浅色控件（深色主题），显示时为蓝色（浅色主题）/对应强调色（深色主题）。
3. **Given** 主题切换按钮，**When** 当前为浅色，**Then** 按钮显示「浅色」；点击后切到深色并显示「深色」；再点切回「浅色」。
4. **Given** 「登出」入口，**When** 查看右上角，**Then** 不存在（位置由垃圾箱图标占用）。
5. **Given** 手动创建表单（+），**When** 标题非空时按 Enter 或点击确认按钮，**Then** 均可成功创建；仍仅标题必填。
6. **Given** 日视图或全部视图中的活跃卡片网格，**When** 按排浏览，**Then** 按创建时间排列：第一排最左为最新创建，同排向右越来越早；下一排接续更早，整体向右向下越来越早。
7. **Given** 日/全部视图所在页面宽度变化，**When** 缩放或调整窗口，**Then** 优先增加/减少每排卡片数量，而非优先把单卡横向拉得很宽（横向拉伸阈值降低）。
8. **Given** 已安排且起止跨多天的日程，**When** 在月视图单日格中展示，**Then** 不做跨格连接条，仅比普通卡片略宽以示区别；**When** 在周视图，**Then** 仍保留跨列连续条带。
9. **Given** 任意主视图，**When** 查看页面边缘，**Then** 留有页边距；周/月视图最左侧格子或列不超出页面可见边界。
10. **Given** 周视图或月视图同一格子/列内多条日程，**When** 展示，**Then** 竖向排列不再相互明显挤压到难以辨认（拥挤问题修复）。

### User Story 8 - 创建与修改时间戳在详情可见 (Priority: P8)

作为所有者，我希望在打开详情时看到创建时间与最后修改时间，以便追溯何时写下与最近改动，而不占用卡片表面空间。

**Why this priority**: 可独立交付的只读元数据展示；依赖保存路径更新「最后修改时间」。

**Independent Test**: 新建卡片打开详情可见创建时间；编辑保存后再开，最后修改时间更新；常规卡片面不显示这两行。

**Acceptance Scenarios**:

1. **Given** 任意卡片被创建，**When** 打开详情，**Then** 以小号浅色文字展示「创建时间」与「最后修改时间」（示例格式：`创建时间：2026-0715-1639`）。
2. **Given** 卡片经确认保存修改，**When** 再次打开详情，**Then** 「最后修改时间」反映最近一次成功保存；常规卡片表面仍不显示这两项。
3. **Given** 仅打开详情后点外部放弃或点「重置」，**When** 未确认保存，**Then** 「最后修改时间」不变。

### Edge Cases

- 恢复垃圾箱卡片时，若其标题已与另一张活跃卡片冲突：拒绝恢复并明确提示标题冲突，卡片仍留在垃圾箱。
- 永久删除后，允许新建卡片使用原标题（与「仅对活跃卡片做重名校验」一致）。
- 已安排但结束时间早于起始时间：拒绝保存并就地提示，与其他校验一致。
- 仅填结束时间未填起始时间：视为无效时间填写，拒绝保存并提示须填写起始时间，或清空所有时间字段以保存为未安排。
- 坐标视图中重要度或紧急度为边界值 0 或 10：仍正确落在轴线对应位置。
- 某坐标点仅一张卡片：仍显示为圆（可较小），悬停列出该唯一任务名。
- 日视图下打开坐标视图时，若当日无活跃已安排卡片：展示空坐标系（无圆），不报错。
- 完成操作针对已在垃圾箱的卡片：入口不可用或不出现（仅活跃卡片可完成/删除进箱）。
- 旧「高/中/低」以外的异常历史值：回落到默认中档数值（见 Assumptions）。
- 历史「截止型」（仅有单一 deadline、无起止区间语义）卡片在升级迁移时：清空所有时间字段并变为「未安排」；仅出现在全部视图，直到所有者重新填写起始时间。
- 历史「持续型」（已有起止时间）卡片：保留起始与结束时间，直接成为新模型下的「已安排」区间卡片。
- 垃圾箱内点击卡片：可打开只读详情；箱内详情不提供字段编辑、不提供完成入口；恢复与永久删除仍在垃圾箱视图操作（或只读详情旁提供同等操作，但不改变只读约束）。
- 全局搜索命中已永久删除的卡片：不应出现（永久删除后不可再被搜索）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将重要程度与紧急程度建模为 0~10 的整数（含 0 与 10），并在所有者点击时提供最下 0、最上 10 的竖向数字选择。
- **FR-002**: 系统 MUST 在升级时将既有「高 / 中 / 低」重要度与紧急度转换为约定的 0~10 数值（Assumptions），且转换后所有者可再编辑。
- **FR-003**: 系统 MUST 取消「时间性质」属性；卡片时间状态仅能为「已安排」（所有者填写了起始时间，结束时间可选）或「未安排」（未填写任何时间字段，且不得代填起始时间）。
- **FR-003a**: 升级迁移时，历史「截止型」卡片 MUST 清空全部时间字段并成为「未安排」；历史「持续型」卡片 MUST 保留起止时间并成为「已安排」。
- **FR-004**: 「未安排」卡片 MUST 仅出现在全部视图；「已安排」卡片 MUST 按其时间出现在相应日 / 周 / 月视图，并仍可出现在全部视图。
- **FR-004a**: 全部视图时间相关筛选 MUST 以「已安排 / 未安排」替换原「时间性质」与「有无时间」；**分类**、重要度、紧急度等其余筛选 MUST 保留可用。
- **FR-005**: 系统 MUST 支持将活跃卡片「完成」或「删除」后进入统一垃圾箱；完成 MUST NOT 二次确认；删除 MUST 二次确认。
- **FR-006**: 进入垃圾箱的卡片 MUST 从日 / 周 / 月 / 全部 / 坐标等所有常规视图中消失。
- **FR-007**: 页面右上角 MUST 提供垃圾箱图标入口（取代原登出按钮位置）；MUST NOT 再提供登出按钮。
- **FR-008**: 垃圾箱视图 MUST 以类似全部视图的网格/列表呈现，并按进入垃圾箱的时间倒序排列（最近在左上）。
- **FR-009**: 垃圾箱内 MUST 区分进箱原因：已完成显示对勾标记，已删除显示红色圆形标记。
- **FR-010**: 垃圾箱内每张卡片 MUST 支持「恢复」为活跃，以及「永久删除」（不可逆，须二次确认）。
- **FR-010a**: 垃圾箱内卡片 MUST 可打开只读详情（可查看不可改）；MUST NOT 在箱内编辑字段或经由详情完成；修改内容 MUST 先恢复为活跃。
- **FR-010b**: 全局标题搜索 MUST 包含垃圾箱中的卡片；匹配的垃圾箱候选项 MUST 标注「已完成」或「已删除」；点击此类候选 MUST 打开只读详情。
- **FR-011**: 完成与删除、恢复与永久删除 MUST 复用统一的卡片生命周期语义（同一套进箱/出箱/消亡规则）。
- **FR-012**: 系统 MUST 在卡片详情右上角，以及日视图与全部视图每张活跃卡片右侧，提供语义一致的完成方框入口（点击出对勾即完成进箱）。
- **FR-013**: 日视图与全部视图 MUST 各提供「坐标视图」入口；打开后在页面中心展示以重要度 5、紧急度 5 为原点的二维坐标系（横轴紧急、纵轴重要，右上为更重要更紧急）。
- **FR-014**: 坐标视图 MUST 仅展示当前所在视图（日或全部）中的活跃卡片，按（紧急度, 重要度）落点；同点聚合为圆且任务越多圆越大；悬停列出该圆任务名称（过多时可滚动查看全部，或展示前若干条并以「+N」标明其余）；点击圆 MUST NOT 触发额外行为；垃圾箱卡片 MUST NOT 出现。
- **FR-015**: 打开卡片详情后 MUST 可直接编辑各属性；右下角 MUST 为「重置」（有未保存修改前不可用；将草稿恢复为打开时快照且不关闭）与「确认」（保存并关闭）；点击详情外区域 MUST 放弃修改并关闭；详情编辑/保存路径 MUST NOT 使用二次确认弹窗。文案「重置」MUST NOT 与垃圾箱「恢复」混用。
- **FR-016**: 「确认」时若标题为空或与其他活跃日程重名，系统 MUST 就地提示错误，且不关闭、不保存。
- **FR-017**: 每张卡片 MUST 记录创建时间与最后修改时间；仅在详情内以小号浅色文字展示（格式示例 `创建时间：2026-0715-1639`），MUST NOT 在常规卡片面上显示。
- **FR-018**: 应用默认启动时右侧 AI 助手 MUST 为隐藏；AI 显隐按钮文案 MUST 为「AI」，并按隐藏/显示使用白/蓝（及深色主题对应配色）。
- **FR-019**: 主题切换按钮 MUST 只显示当前主题名（「浅色」或「深色」），点击在二者间切换。
- **FR-020**: 详情内删除文案 MUST 为「删除」；删除二次确认框 MUST 比第三轮更窄。
- **FR-021**: 手动创建 MUST 支持在标题非空时用 Enter 或确认按钮完成创建，且仅标题必填。
- **FR-022**: 日视图与全部视图的活跃卡片 MUST 按创建时间从新到旧、自左向右、自上而下排列。
- **FR-023**: 日/全部视图在宽度变化时 MUST 降低卡片横向拉伸倾向，使每排卡片数量更易随宽度变化。
- **FR-024**: 跨多天的已安排区间日程在月视图中 MUST NOT 做跨格连接，仅略宽于普通卡片；周视图 MUST 保留跨列连续条带。
- **FR-025**: 所有主视图 MUST 保留页边距；周/月最左侧列/格 MUST NOT 超出页面可见边界。
- **FR-026**: 周/月视图中同一区域内多条日程的竖向排列 MUST 避免相互严重挤压导致难辨。
- **FR-027**: 标题唯一性、仅标题必填、未安排只进全部等规则 MUST 与新时间模型及垃圾箱活跃范围彼此自洽（重名仅相对活跃卡片）。
- **FR-028**: 本轮 MUST NOT 改变单用户鉴权方式；MUST NOT 让 AI 执行日程增删改查或触发日程数据联动——所有生命周期操作经 UI/结构化路径完成。

### Key Entities

- **日程卡片（Schedule Card）**：唯一日程数据单元；含标题、描述、分类、重要度（0~10）、紧急度（0~10）、可选起始时间、可选结束时间、创建时间、最后修改时间、生命周期状态。
- **时间状态**：由时间字段推导——已安排（有起始时间）或未安排（无任何时间字段）；结束时间仅表示区间上界，NOT 旧「截止型 deadline」；无独立「时间性质」属性。
- **生命周期状态**：活跃、已完成（在垃圾箱）、已删除（在垃圾箱）；永久删除后不再作为可恢复实体存在。
- **垃圾箱**：存放已完成与已删除卡片的归档集合；按进入垃圾箱时间排序；支持恢复与永久删除。
- **坐标点聚合**：同一（紧急度, 重要度）上多张活跃卡片的视觉聚合，用于坐标视图圆与悬停列表。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 所有者可在 10 秒内将一张活跃日程从日视图或全部视图一键完成并在垃圾箱中看到带对勾标记的该项。
- **SC-002**: 在含至少 5 张垃圾箱卡片的情况下，所有者可在 30 秒内完成「打开垃圾箱 → 恢复一张 → 在常规视图确认出现」全流程。
- **SC-003**: 100% 的未安排卡片在手动验收中仅出现在全部视图，不出现在日/周/月视图；填写起始时间后 100% 出现在对应时间视图。
- **SC-004**: 重要度与紧急度在创建/编辑路径下均可选到 0 与 10；历史三档数据转换后抽查 100% 落在 0~10。
- **SC-005**: 在日视图与全部视图，所有者可打开坐标视图并在 15 秒内通过悬停读出某一聚合圆内的任务名称（含滚动或「+N」知晓全部数量）。
- **SC-006**: 详情路径下「直接改字段 → 外部点击放弃」与「改字段 → 重置 → 确认无变更」在验收用例中 100% 符合「未确认则不写入」。
- **SC-007**: 默认进入应用时 AI 面板为隐藏；顶栏无登出、有垃圾箱；主题按钮文案与当前主题一致——首屏可用性检查一次通过。
- **SC-008**: 在代表性桌面与窄屏宽度下，日/全部每排卡片数随宽度变化可观察到增减，且周/月左侧不越界、同格多日程可辨认（修复项验收清单全部勾选）。

## Assumptions

- **优先级旧值映射**：历史「高」→ 8，「中」→ 5，「低」→ 2；无法识别的异常值 → 5。
- **新建默认优先级**：未显式选择时，重要程度与紧急程度默认均为 5（与坐标原点一致，便于未分级任务落在中心附近）。
- **详情「确认」无修改时**：允许点击，效果为关闭详情且不产生新的「最后修改时间」。
- **标题唯一性范围**：仅对**活跃**卡片校验；垃圾箱内卡片不占用标题；永久删除后标题可复用；恢复时若冲突则拒绝恢复。
- **「进入垃圾箱的时间」**：完成或删除成功的时刻；恢复再进箱视为新的进箱时间。
- **最后修改时间**：仅在创建成功与详情「确认」保存成功时更新；完成/删除/恢复本身若未改内容字段，可不视为内容修改（进箱时间单独记录）；若实现上将生命周期变更也更新最后修改时间，须在详情中仍可读且与创建时间区分——默认可只在内容字段确认保存时更新最后修改时间。
- **坐标视图关闭方式**：点击坐标视图以外区域或提供明确关闭控件即可关闭；关闭后回到触发前的日或全部视图（不另开路由记忆需求）。
- **周/月不提供卡片侧完成方框**：与需求「日视图和全部视图」一致；周/月仍可通过打开详情完成。
- **单用户与 AI 边界**：沿用宪法——四字符验证码会话；AI 纯对话不操作日程。
- **宪法卡片模型**：已由宪法 v1.3.0 与本轮模型对齐（已安排/未安排 + 0~10）。
- **数据保留**：垃圾箱内卡片在所有者永久删除前一直保留，不设自动清空期限（本轮未要求到期清理）。
- **截止型迁移**：不把原 deadline 映射为起始或结束；直接清空时间，降级为未安排，避免在无「截止型」语义的新模型中误解单一时刻。
- **垃圾箱详情**：只读；恢复/永久删除是箱内写操作的唯一途径（生命周期），内容编辑仅限活跃态即时编辑流程。
- **详情「重置」**：仅重置本次打开后的草稿，不关闭详情，不改变生命周期状态。
- **搜索范围**：标题搜索覆盖活跃 + 垃圾箱（已完成/已删除）；永久删除后不再出现在搜索结果。
- **全部视图筛选**：时间维度仅「已安排 / 未安排」；分类筛选必须保留；不再暴露「时间性质」或独立的「有无时间」筛选项。
- **坐标圆交互**：信息仅通过悬停展示（可滚动或 +N）；点击不打开详情、不固定面板、不退出坐标视图；关闭坐标须点外围或显式关闭控件。
