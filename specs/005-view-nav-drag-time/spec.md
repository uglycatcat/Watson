# Feature Specification: 视图导航、拖拽归档与时间模型收紧

**Feature Branch**: `005-view-nav-drag-time`

**Created**: 2026-07-16

**Status**: Draft

**Input**: User description: "这是 Watson 的第五轮迭代，命名为「视图导航、拖拽归档与时间模型收紧」。在已上线的 001~004 之上，补齐各视图的时间导航、把日视图的优先级坐标图常驻化、新增拖拽删除、修复导航栏日历相关缺陷，并收紧日程的时间填写规则。"

## Clarifications

### Session 2026-07-16

- Q: 时间规则三种互斥情形与历史仅开始卡？ → A: 已安排必有起止；只填结束→开始=创建时刻；填开始→结束自动补开始+24h 且可改不能清空；皆空=未安排；库内仅开始卡兜底结束=开始+24h。
- Q: 拖拽到垃圾箱的语义？ → A: 等同「删除」（红圆标记），不弹二次确认；详情内删除仍二次确认。
- Q: 日视图坐标图形态？ → A: 仅日视图右侧凹陷方框常驻；全部视图保持按钮弹出。
- Q: 全部视图是否显示日期控件？ → A: 全部视图恢复显示且可调，但不影响主列表；垃圾箱不显示日期控件。
- Q: 导航栏「清除」入口？ → A: 移除并替换为「回到今天」；锚定日期始终有效、不可为空。
- Q: 登录页备案占位？ → A: 只留空位，不填真实备案号；明暗主题均不破坏登录视觉。
- Q: 三视图导航粒度？ → A: 日=±1 天+今天；月=±1 月+本月；周维持上一周/本周/下一周。
- Q: 再次修改开始时间时结束如何处理？ → A: 仅当结束为空或早于新开始时自动补为开始+24h；否则保留原结束。
- Q: 哪些界面元素可拖到垃圾箱？ → A: 日/全部卡片、周/月单元格内芯片、周视图跨天长条均可拖。
- Q: 触摸/移动端是否必须支持拖拽删除？ → A: 否。精细指针（桌面）MUST 支持拖到垃圾箱；触摸或粗指针设备本轮可不实现触摸拖拽，降级为详情内「删除」（仍二次确认）或既有完成入口；不得另开数据路径。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 时间填写三种互斥情形 (Priority: P1)

作为所有者，我希望创建/编辑日程时时间规则清晰且互斥——未安排、只填结束、或起止齐全——以便不再出现「只有开始没有结束」的已安排卡片，并与日历/全部视图过滤一致。

**Why this priority**: 取代第四轮时间模型核心规则；影响创建、编辑、迁移与所有日历取数，是本轮数据正确性底座。

**Independent Test**: 分别以三种路径保存卡片，确认未安排只在全部；只填结束时开始被设为创建时刻；填开始后结束自动为开始+24h 且不可最终留空；历史「仅开始」卡升级后具备结束时间。

**Acceptance Scenarios**:

1. **Given** 创建或编辑表单中开始与结束均未填写，**When** 保存成功，**Then** 卡片为「未安排」，仅出现在全部视图，不出现在日/周/月视图。
2. **Given** 所有者只填写结束时间、未填开始时间，**When** 保存，**Then** 卡片为「已安排」；开始时间默认为**创建该卡片的时刻**（形成「创建时刻 → 结束」区间），并按该区间进入相应日历视图。
3. **Given** 所有者首次填写开始时间（结束为空），**When** 开始时间被设定，**Then** 结束时间自动补为「开始时间 + 24 小时」；用户可再修改结束，但最终保存时结束 MUST NOT 为空（不可清空结束而只留开始）。
3b. **Given** 卡片已有合法结束时间，**When** 所有者修改开始时间且新开始仍 ≤ 原结束，**Then** 保留原结束；**When** 新开始使原结束变为空或早于新开始，**Then** 结束自动补为新开始 + 24 小时。
4. **Given** 已安排路径下结束时间为空或结束早于开始，**When** 尝试保存，**Then** 拒绝并就地提示，不写入非法状态。
5. **Given** 历史存在「仅有开始、无结束」的已安排卡片，**When** 产品升级后加载，**Then** 系统为其补齐结束时间（见 Assumptions），使之符合「已安排必有起止」。
6. **Given** 三种情形，**When** 所有者使用表单，**Then** 情形互斥且可理解：清空全部时间→未安排；只留结束→情形②；有开始则必须有结束→情形③。

### User Story 2 - 拖拽卡片到垃圾箱归档 (Priority: P2)

作为所有者，我希望在任意常规视图把卡片拖到右上角垃圾箱图标上即可删除进箱，以便快速清理而不必打开详情或二次确认。

**Why this priority**: 新增高频归档入口；必须与第四轮「删除→垃圾箱、红圆标记」语义一致，且与详情删除（仍二次确认）区分。

**Independent Test**: 从日/周/月/全部拖一张活跃卡到垃圾箱图标松手；卡从常规视图消失；垃圾箱中以已删除红圆呈现；详情内点删除仍弹二次确认。

**Acceptance Scenarios**:

1. **Given** 所有者在日或全部视图的卡片网格、周/月单元格内芯片、或周视图跨天长条上看到活跃日程，**When** 将该元素拖到右上角垃圾箱图标上并松手，**Then** 对应卡片按「删除」生命周期进入垃圾箱（已删除红圆标记），并从所有常规视图（含坐标）消失；**不**弹出二次确认。
2. **Given** 拖拽删除成功，**When** 打开垃圾箱，**Then** 该项出现且与详情删除进箱的项语义一致（可恢复、可永久删除）。
3. **Given** 所有者打开卡片详情并点「删除」，**When** 操作，**Then** 仍须二次确认（拖拽路径不改变该路径）。
4. **Given** 拖拽未放到垃圾箱图标上（取消或放回原处），**When** 松手，**Then** 卡片不进箱、数据不变。
5. **Given** 垃圾箱视图或已进箱卡片，**When** 尝试拖拽归档，**Then** 不适用或不可再拖入删除（仅活跃卡片可拖拽删除）。
6. **Given** 全局搜索下拉候选，**When** 尝试拖拽，**Then** 不作为拖拽删除来源（须在主视图卡片/芯片/长条上拖）。

### User Story 3 - 日/月时间导航与导航栏日期控件修复 (Priority: P3)

作为所有者，我希望日/月像周一样能前后切换并回到当前，且导航栏日期永不被清空、全部视图仍显示日期控件，以便浏览日历时不会因「清除」把界面清空。

**Why this priority**: 修复阻塞可用性的导航缺陷，并补齐日/月与周对等的时间导航。

**Independent Test**: 日视图上一天/今天/下一天；月视图上一月/本月/下一月；触发原「清除」位置变为「回到今天」且日期不能被清空；全部视图仍显示日期控件但不改变全部列表内容；垃圾箱不显示日期控件。

**Acceptance Scenarios**:

1. **Given** 日视图，**When** 使用「前一 / 回到当前 / 后一」，**Then** 分别切换到前一天、今天、后一天，主内容随锚定日期更新。
2. **Given** 月视图，**When** 使用「前一 / 回到当前 / 后一」，**Then** 分别切换到上一月、本月、下一月。
3. **Given** 周视图，**When** 查看导航，**Then** 仍为上一周 / 本周 / 下一周（行为保持）。
4. **Given** 导航栏日期选择器，**When** 查看控件，**Then** **不存在**会把锚定日期清空的「清除/删除」入口；锚定日期始终为有效日期。
5. **Given** 原清除入口位置，**When** 点击「回到今天」（或同等文案），**Then** 锚定日期重置为今天，与各视图「回到当前」语义一致。
6. **Given** 全部视图，**When** 查看导航栏，**Then** 日期控件仍然显示且可调整；调整**不**改变全部视图主列表内容（全部不按单一日期过滤）。
7. **Given** 垃圾箱视图，**When** 查看导航栏，**Then** 无需显示日期控件（按进箱时间排序）。

### User Story 4 - 日视图常驻优先级坐标图 (Priority: P4)

作为所有者，我希望在日视图右侧始终看到当日活跃卡片的优先级坐标分布，而不必再点按钮打开浮层。

**Why this priority**: 改变第四轮日视图交互形态；全部视图仍保持按钮打开，范围边界清晰。

**Independent Test**: 进入日视图右侧见凹陷圆角方框内的坐标图；无「坐标视图」按钮；全部视图仍有按钮点击打开；日视图坐标仅含当日活跃卡。

**Acceptance Scenarios**:

1. **Given** 所有者打开日视图，**When** 主区域呈现，**Then** 右侧常驻一块带圆角、凹陷质感背景的方形区域，内嵌二维优先级图（横轴紧急、纵轴重要，原点 5/5，右上更重更急）；行为沿用第四轮坐标图（分桶、悬停名单、点击无额外行为等）。
2. **Given** 日视图，**When** 查找「坐标视图」按钮，**Then** 该按钮不存在。
3. **Given** 全部视图，**When** 使用坐标能力，**Then** 仍通过按钮点击打开浮层（第四轮方式不变）。
4. **Given** 日视图右侧坐标，**When** 渲染，**Then** 仅包含该日视图当前活跃卡片；已完成/已删除不出现。

### User Story 5 - 登录页备案占位 (Priority: P5)

作为所有者（及未来合规需要），我希望登录页下方预留备案信息区域，以便日后放入 ICP 等图标与文字而不破坏现有登录视觉。

**Why this priority**: 合规预留；本轮不填真实备案号，独立可验。

**Independent Test**: 登录页下方见占位区域；浅色/深色主题下布局与风格不破坏；占位内可为空或中性提示，无真实备案号要求。

**Acceptance Scenarios**:

1. **Given** 未登录用户打开登录页，**When** 查看页面下方，**Then** 存在明确预留的备案占位区域。
2. **Given** 浅色与深色主题，**When** 查看该占位，**Then** 不破坏登录页现有视觉风格与可用性。
3. **Given** 本轮交付，**When** 检查占位内容，**Then** 不要求填入真实备案号（可留空或中性占位文案）。

### User Story 6 - 周/月视图视觉收紧 (Priority: P6)

作为所有者，我希望周视图日框与月视图底部上收、周内长条更粗且顶端略下移并对齐间隔，以便页面底部更透气、条带更易辨认。

**Why this priority**: 视觉 polish；不阻塞 P1–P4，但同属本轮交付。

**Independent Test**: 对照场景逐项目视验收周框上收、月底留白、长条粗细约 2.5 倍、顶端略下移、条间间隔对齐。

**Acceptance Scenarios**:

1. **Given** 周视图，**When** 查看每日框体，**Then** 相对第四轮上边沿整体略向上收，页面底部留白增加，内容不贴底边。
2. **Given** 月视图，**When** 查看最下一排与整体，**Then** 下边沿上收、整体略向上收缩，底部留白增加。
3. **Given** 周视图跨天/日内长条，**When** 比较，**Then** 粗细约为当前约 2.5 倍；顶端起始位置略向下，不顶格最上沿；彼此间隔对齐。

### Edge Cases

- 只填结束且结束早于「创建时刻」：拒绝保存并提示（结束不得早于开始）。
- 修改开始时间时若用户已手动改过结束：默认仍保证结束非空；若结束早于新开始则自动调整为开始+24h 或拒绝保存（见 Assumptions：自动纠正为开始+24h 并允许再改）。
- 拖拽经过其他 UI 元素松手：不删除；仅命中垃圾箱投放区才删除。
- 拖拽进行中刷新/断网：不产生部分状态；失败则卡片仍活跃并提示。
- 全部视图下改导航日期：列表不变；切换回日/周/月时使用该锚定日期。
- 窄屏日视图：右侧坐标方框仍可用（可缩小或纵向堆叠，见 Assumptions），不得完全消失导致无法看到优先级分布。
- 历史未安排卡：不受起止补齐影响，保持未安排。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将卡片时间规则收紧为三种互斥情形：① 起止皆空 → 未安排；② 仅结束有值 → 已安排，开始 = 创建时刻；③ 有开始 → 已安排且结束必填（首次填开始或结束为空/非法时结束默认开始+24h，最终不得为空）。
- **FR-001a**: 修改开始时间时，若原结束仍 ≥ 新开始则 MUST 保留原结束；若结束为空或早于新开始则 MUST 自动补为新开始+24h。
- **FR-002**: 「已安排」卡片 MUST 同时具备开始与结束时间；MUST NOT 再存在「仅开始无结束」的合法持久状态。
- **FR-003**: 未安排卡片 MUST 仅出现在全部视图；已安排卡片 MUST 按其起止区间进入相应日/周/月视图，并仍可出现在全部视图。
- **FR-004**: 升级时 MUST 将历史「仅开始无结束」卡片补齐结束时间（Assumptions），使之符合 FR-002。
- **FR-005**: 在支持精细指针拖放的设备上，所有者 MUST 能将以下活跃日程表象拖到右上角垃圾箱图标（含合理扩大热区）松手完成删除进箱：日/全部网格卡片、周/月单元格内芯片、周视图跨天长条；该路径 MUST NOT 二次确认；进箱原因与详情删除一致（已删除标记）。触摸/粗指针设备本轮 MAY 不提供拖拽，MUST 仍可通过详情删除（二次确认）完成同等进箱（见 Clarifications）。
- **FR-005a**: 全局搜索候选 MUST NOT 作为拖拽删除来源。
- **FR-005b**: 拖拽删除若请求失败（含断网），卡片 MUST 保持活跃（或回滚乐观更新），并向所有者提示失败；MUST NOT 留下「视图已消失但未进箱」的不一致状态。
- **FR-006**: 详情内「删除」MUST 继续二次确认；拖拽 MUST NOT 改变完成/恢复/永久删除等既有垃圾箱语义。
- **FR-007**: 日视图与月视图 MUST 提供与周视图对等的「前一 / 回到当前 / 后一」时间导航（粒度分别为日、月）；周视图保持上一周/本周/下一周。
- **FR-008**: 导航栏锚定日期 MUST 始终为有效日期；MUST 移除会清空锚定日期的「清除/删除」入口。
- **FR-009**: 原清除入口 MUST 替换为「回到今天」（或同等明确文案），点击后将锚定日期设为今天。
- **FR-010**: 日/周/月/全部视图下导航栏日期控件 MUST 保持显示；全部视图下调整日期 MUST NOT 改变全部主列表内容；垃圾箱视图 MUST NOT 要求显示日期控件。
- **FR-011**: 日视图 MUST 取消「坐标视图」按钮，并在右侧常驻凹陷圆角方框内的二维优先级坐标图（原点 5/5，行为沿用第四轮）；全部视图坐标入口方式 MUST 保持第四轮按钮打开不变。
- **FR-012**: 登录页下方 MUST 预留备案占位区域；本轮 MUST NOT 要求真实备案号；明暗主题下 MUST NOT 破坏登录页既有风格。
- **FR-013**: 周视图日框与月视图底部 MUST 相对第四轮上收并增加页底留白；周视图日程长条粗细约增至 2.5 倍，顶端略下移且条间距对齐。
- **FR-014**: 本轮 MUST NOT 改变单用户鉴权；MUST NOT 让 AI 操作日程；拖拽删除 MUST 仅作为触发既有「删除进垃圾箱」的 UI 入口。

### Key Entities

- **日程卡片**：沿用第四轮字段；时间状态由起止推导——未安排（皆空）或已安排（起止皆有）。
- **创建时刻**：卡片首次成功创建的时间戳；在「只填结束」路径下用作默认开始时间。
- **锚定日期**：导航栏与日/周/月视图共享的当前浏览日期；不可为空。
- **拖拽删除手势**：从活跃卡片到垃圾箱投放区的拖放，语义等同软删除进箱且跳过确认。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 验收用例中 100% 的新保存卡片符合三种互斥时间情形之一；抽查中不存在「仅开始无结束」的活跃已安排卡。
- **SC-002**: 所有者可在 15 秒内从全部或日视图拖一张卡进垃圾箱，并在垃圾箱中看到红圆「已删除」标记且无确认弹窗。
- **SC-003**: 日视图连续切换前一天/今天/后一天、月视图切换上一月/本月/下一月各一次，主内容与锚定日期 100% 一致。
- **SC-004**: 无法通过 UI 将锚定日期清空；「回到今天」一次操作即可恢复为今天。
- **SC-005**: 全部视图下日期控件可见；切换到全部后主列表不因改日期而过滤消失。
- **SC-006**: 进入日视图即可在右侧看到坐标方框而无需点击「坐标视图」；全部视图仍用按钮打开。
- **SC-007**: 登录页备案占位在浅/深色主题下均可辨认且不破坏登录布局。
- **SC-008**: 周/月视觉项（底留白、长条约 2.5 倍粗、顶端下移）在目视验收清单中全部勾选通过。

## Assumptions

- **历史仅开始卡迁移**：结束时间 = 开始时间 + 24 小时（与表单默认一致）；所有者可再编辑。
- **只填结束时的「创建时刻」**：使用该卡片的 `创建时间`（首次成功创建）；编辑已有卡时若补「只填结束」路径，开始取原创建时间而非编辑时刻。
- **填/改开始时的结束**：首次填开始（结束空）→ 自动补开始+24h；再次改开始时仅当结束空或早于新开始才重补，否则保留原结束；用户可改结束但不能清空。
- **拖拽投放命中**：垃圾箱图标及其合理扩大的投放热区（如额外 padding / 命中盒子）；松手时以命中热区为准。
- **拖拽语义定案**：拖放到垃圾箱 = 软删除进箱（红圆），无确认；与完成（对勾）区分。
- **拖拽来源**：日/全部卡片、周/月芯片、周跨天长条；不含搜索候选、不含垃圾箱内项。
- **拖拽平台范围**：HTML5 DnD 面向精细指针；触摸/粗指针不实现触摸拖拽，降级见 Clarifications / FR-005。
- **拖拽失败**：复用既有 mutation 错误提示；失败时列表 invalidate/回滚，卡片仍活跃。
- **日视图窄屏**：坐标方框可缩至不小于约 200×200 CSS 像素，或主区与坐标上下堆叠，但不得移除常驻坐标。
- **备案占位**：可为空块或浅色「备案信息预留」类中性文字，不链到外站。
- **长条 2.5 倍**：以第四轮周视图跨天/条带视觉厚度为基线目视约 2.5 倍，允许 ±20% 以匹配栅格。
- **宪法时间措辞**：宪法 **v1.3.1** 已与本轮对齐（已安排必有起止）；以宪法与本 spec 为准。
- **边界不变**：单用户会话、AI 不写日程、垃圾箱完成/删除/恢复/永久删除语义沿用 004。
