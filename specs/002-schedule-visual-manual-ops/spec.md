# Feature Specification: 日程可视化与手动操作增强

**Feature Branch**: `002-schedule-visual-manual-ops`

**Created**: 2026-07-06

**Status**: Draft

**Input**: User description: "这是对已实现功能 001-conversational-scheduling 的第二轮界面交互迭代。根据首轮测试反馈，需要改进日程的浏览体验、AI 助手栏的可控性，并补齐不依赖对话的手动操作入口。包含：主题偏好收敛为明/暗二选一、AI 助手栏可隐藏与可调宽、日/周/月/全部四种视图的真实日历呈现、卡片详情与界面删除、顶部手动创建日程表单。不改变卡片数据结构与后端增删改查逻辑。"

## Clarifications

### Session 2026-07-06

- Q: 月视图「+N 更多」或日期格点击后如何查看该日完整列表？ → A: 侧滑/抽屉列出该日全部卡片（不切换至日视图）
- Q: 月视图中跨日持续型卡片如何展示？ → A: 跨格连续条带（起始格显示完整标题，条带跨越所覆盖日期格）
- Q: 周视图中跨日持续型卡片如何展示？ → A: 跨列连续条带（起始列显示完整标题，条带跨越所覆盖日列，与月视图语义一致）
- Q: AI 助手栏显隐状态应持久化到哪一级？ → A: 仅会话级（当前 tab/会话内记住，关闭浏览器后以新会话打开时恢复默认显示）
- Q: 卡片详情应以何种形式呈现？ → A: 居中模态对话框（遮罩 + 居中面板，与日抽屉职责分离）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看卡片详情并从界面删除 (Priority: P1)

作为所有者，我希望在任意视图中点击一张日程卡片即可查看其完整属性，并在详情中直接发起删除，以便不依赖 AI 对话也能审阅和清理日程。

**Why this priority**: 月/周视图及后续手动操作均依赖「点击卡片 → 查看详情」这一基础交互；删除是高频写操作，界面入口补齐后价值立即可验。

**Independent Test**: 在任意视图点击一张卡片，确认详情展示标题、时间性质、重要/紧急度、分类等字段；点击删除并经二次确认后，卡片从当前视图及全部视图中消失。

**Acceptance Scenarios**:

1. **Given** 所有者已登录且主区域存在日程卡片，**When** 点击任意卡片，**Then** 系统以居中模态对话框展示详情（遮罩背景 + 居中面板），至少包含：标题、时间性质（持续型的开始与结束时间，或截止型的 deadline）、重要程度、紧急程度、分类；若卡片含描述则一并展示；关闭模态后用户仍处原视图上下文。
2. **Given** 详情模态已打开，**When** 点击「删除该日程」，**Then** 系统在模态之上或模态内弹出二次确认（明确指向该卡片标题），用户未确认前不执行删除。
3. **Given** 二次确认已展示，**When** 用户确认删除，**Then** 卡片被删除、详情关闭，当前视图及其他视图在数据刷新后不再显示该卡片。
4. **Given** 二次确认已展示，**When** 用户取消，**Then** 卡片保持不变，详情仍可继续浏览或关闭。
5. **Given** 所有者通过 AI 对话删除卡片，**When** 删除成功，**Then** 行为与界面删除一致（均需二次确认、删除后各视图同步更新）。

### User Story 2 - 月视图日历网格浏览 (Priority: P2)

作为所有者，我希望月视图以当月日历网格展示日程，以便一眼掌握整月安排分布，而非平铺列表。

**Why this priority**: 首轮反馈中月视图缺乏日历形态是核心体验缺口；网格化是「可视化增强」的主诉求。

**Independent Test**: 创建跨多日的若干卡片，切换至月视图，确认按周排列的日期格子、卡片归属日期正确；点击格子内卡片可打开详情。

**Acceptance Scenarios**:

1. **Given** 所有者切换至月视图，**When** 查看主区域，**Then** 呈现当月日历：按周排列的日期网格，每格标注日期，格内展示该日日程卡片。
2. **Given** 某日有多张卡片，**When** 卡片数量超出格子可舒适展示的上限，**Then** 系统优先展示最重要的若干张（按重要度 × 紧急度排序），其余以「+N 更多」折叠提示表示。
3. **Given** 月视图中某日卡片超出格子展示上限，**When** 用户点击该日期格或「+N 更多」，**Then** 从主区域边缘滑出抽屉（或等效侧滑面板），列出该日全部日程卡片（含详情入口），用户仍停留在月视图上下文；关闭抽屉后回到月历网格。
4. **Given** 持续型卡片跨越多日，**When** 在月视图中展示，**Then** 以跨格连续条带呈现：条带横跨其所覆盖的全部日期格，完整标题显示在起始日期格，用户可识别该安排涉及哪些日期；点击条带任意可见部分 MUST 打开该卡片详情。
5. **Given** 持续型卡片跨月（如 1 月 30 日–2 月 2 日），**When** 分别查看两个月月视图，**Then** 各月网格内 MUST 在对应日期格显示该条带的可见段（起始月从起始日起、结束月至结束日止），语义上为同一安排。
6. **Given** 截止型卡片，**When** 在月视图中展示，**Then** 卡片出现在 deadline 所在日期格。
7. **Given** 月视图中某张卡片（含跨格条带或抽屉内列表中的卡片），**When** 用户点击，**Then** 打开卡片详情（同 User Story 1）。

### User Story 3 - 周视图按日分列浏览 (Priority: P3)

作为所有者，我希望周视图以周一至周日（或当前周七天）分列展示每日小卡片，以便聚焦本周安排。

**Why this priority**: 与月视图并列的日历化改进；周是日常规划最常用的粒度之一。

**Independent Test**: 在一周内创建多张卡片，切换周视图，确认七列（或七格）布局、卡片归属日正确；点击小卡片打开详情。

**Acceptance Scenarios**:

1. **Given** 所有者切换至周视图，**When** 查看主区域，**Then** 呈现当前所选周：每一天一列，列内展示当天日程（含单日小卡片与跨列条带）。
2. **Given** 持续型卡片跨越多日且落在当前周内，**When** 在周视图中展示，**Then** 以跨列连续条带呈现：条带横跨其所覆盖的全部日列，完整标题显示在起始日列；点击条带任意可见部分 MUST 打开该卡片详情。
3. **Given** 持续型卡片开始于上周、结束于本周，**When** 查看本周周视图，**Then** 条带从本周第一列（或卡片进入本周的首日列）起展示至结束日列，语义上为同一安排。
4. **Given** 某日无安排（且无跨列条带经过），**When** 查看该列，**Then** 显示空状态或明确「无安排」，而非隐藏该列。
5. **Given** 周视图中某张卡片（含跨列条带或列内小卡片），**When** 用户点击，**Then** 打开卡片详情（同 User Story 1）。
6. **Given** 所有者切换所选周（上一周 / 下一周 / 回到本周），**When** 操作完成，**Then** 主区域更新为对应周的卡片分布。

### User Story 4 - 手动创建日程 (Priority: P4)

作为所有者，我希望通过顶部「+」控件以表单方式直接创建日程，以便在不想对话时也能快速录入。

**Why this priority**: 补齐非对话写路径，与 AI 创建并列；依赖既有创建能力，范围清晰。

**Independent Test**: 点击顶部「+」，填写标题与时间信息并提交，确认新卡片立即出现在当前视图且字段与表单一致。

**Acceptance Scenarios**:

1. **Given** 所有者已登录，**When** 点击顶部主导航栏「+」控件，**Then** 打开创建表单，可填写：标题、时间性质（持续型 / 截止型）、对应时间字段、重要程度、紧急程度、分类；描述为可选。
2. **Given** 表单中必填项（标题、时间性质及对应时间）已有效填写，**When** 提交，**Then** 系统创建一张日程卡片，行为与对话式创建一致（含相同校验规则），并立即在当前视图中可见。
3. **Given** 用户未填写重要度、紧急度或分类，**When** 提交，**Then** 系统采用与对话创建相同的默认值（重要度/紧急度默认「中」，分类默认推断规则与 001 一致）。
4. **Given** 必填项缺失或时间无效（如持续型结束早于开始），**When** 提交，**Then** 系统拒绝创建并给出明确错误提示，不写入不完整卡片。
5. **Given** 创建成功，**When** 所有者切换视图或刷新数据，**Then** 新卡片在各相关视图中正确出现。

### User Story 5 - AI 助手栏显示/隐藏与宽度调整 (Priority: P5)

作为所有者，我希望在任意设备上一键隐藏或显示右侧 AI 助手栏，并在显示时拖动边缘调整宽度，以便主日程区域获得更大空间且布局符合个人习惯。

**Why this priority**: 提升布局可控性，对标 Cursor 侧栏体验；不改变 AI 对话能力本身。

**Independent Test**: 在桌面与移动端分别切换助手栏显隐，确认主区域宽度变化；拖动分隔条调整宽度，刷新页面后宽度仍保留（同一设备）。

**Acceptance Scenarios**:

1. **Given** 所有者已登录，**When** 点击顶部主导航栏中的助手栏开关，**Then** 右侧 AI 助手面板隐藏，主日程区域扩展至全宽；再次点击则恢复显示。
2. **Given** 助手栏处于隐藏状态，**When** 所有者在同一会话内切换视图或刷新页面，**Then** 隐藏状态被记住，主区域保持全宽，直至用户再次打开助手栏。
2b. **Given** 助手栏处于隐藏状态，**When** 所有者关闭浏览器后以新会话重新打开应用，**Then** 助手栏恢复默认显示状态（显隐不跨会话持久化）。
3. **Given** 助手栏可见，**When** 用户拖动主区域与助手栏之间的分隔边缘，**Then** 助手栏宽度实时变化，且被限制在合理最小与最大范围内（窄到仍可使用聊天输入，宽到不过度挤压主区域）。
4. **Given** 用户调整过助手栏宽度，**When** 在同一设备上再次访问，**Then** 恢复上次宽度；**When** 在另一设备访问，**Then** 使用该设备自己的宽度偏好或系统默认宽度（宽度偏好不跨设备同步）。
5. **Given** 窄屏移动设备，**When** 助手栏隐藏，**Then** 主区域占满可用宽度；**When** 显示，**Then** 仍可通过同一顶部开关控制，且核心浏览与对话功能可用。

### User Story 6 - 主题偏好明/暗二选一 (Priority: P6)

作为所有者，我希望主题控件只在浅色与深色之间切换，不再出现「跟随系统」，以便偏好明确、行为可预期。

**Why this priority**: 改动面小、独立可验；清理历史 system 偏好避免无法切换的边界状态。

**Independent Test**: 点击主题控件，确认仅在 light / dark 间切换；将偏好设为 system 的旧数据在加载后视为 light 且可正常切换。

**Acceptance Scenarios**:

1. **Given** 所有者点击主题控件，**When** 当前为浅色，**Then** 切换为深色；**When** 当前为深色，**Then** 切换为浅色；不存在第三种「跟随系统」选项或中间态。
2. **Given** 历史偏好保存为 system，**When** 所有者加载应用，**Then** 界面以浅色主题呈现，且主题控件可正常在明/暗间切换（不得卡在无法切换状态）。
3. **Given** 所有者选择深色主题，**When** 在另一已登录设备加载（共享所有者偏好），**Then** 主题仍为深色（主题偏好继续多设备共享，与助手栏宽度偏好不同）。

---

### Edge Cases

- 月视图某日期卡片极多（如 20+）时，格子内 MUST 折叠显示并保留查看全日列表的路径，不得撑破布局或导致不可点击。
- 持续型跨格条带与同格内单日卡片、其他条带重叠时，MUST 仍可点击各条带打开对应详情，不得因层叠导致无法操作。
- 持续型卡片跨月（如 1 月 30 日–2 月 2 日）时，月视图 MUST 在各自月份网格中展示对应可见条带段，不得丢失或重复创建卡片。
- 周视图中跨列条带与同列内小卡片、其他条带重叠时，MUST 仍可点击各条带打开对应详情。
- 持续型卡片跨周边界（开始于上周、结束于本周）时，周视图 MUST 在本周各覆盖日列展示对应条带段，不得丢失或重复创建卡片。
- 手动创建时选择截止型但 deadline 在过去：系统 SHOULD 允许创建（与 001 一致），但在「即将到期」类查询中按既有规则处理。
- 手动创建表单提交过程中网络失败：系统 MUST 提示错误，不静默丢失用户已填内容（允许用户重试）。
- 删除详情中的卡片后，若该详情由月视图日抽屉或周视图「更多」列表打开，列表 MUST 同步移除已删项。
- 月视图日抽屉打开时，用户 MUST 可关闭抽屉回到月历；抽屉内卡片极多（如 20+）时 MUST 可滚动浏览，不得撑破布局。
- 助手栏宽度拖到最小仍 MUST 能显示输入框与发送能力；拖到最大时主区域 MUST 保留最小可用宽度（具体比例在 plan 阶段量化）。
- 助手栏显隐与会话绑定：同会话内刷新/切视图保持状态；新浏览器会话恢复默认显示。宽度偏好仍按设备本地持久化，二者存储策略独立。
- 助手栏隐藏时，顶部「+」与视图切换等控件 MUST 仍可达，不得被布局挤压或遮挡。
- 日视图：继续以当日卡片列表展示，无需日历网格；无当日安排时显示空状态。
- 全部视图：沿用 001 已有筛选与排序，本轮不削弱；卡片点击同样打开详情。
- 月视图日抽屉已打开时点击其中卡片，MUST 在其上叠加居中详情模态；关闭模态后日抽屉仍保持打开状态（除非用户主动关闭抽屉）。
- 手动删除与对话删除 MUST 共用同一套二次确认语义，不得出现「界面删免确认、对话删需确认」的不一致。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在任意日程视图（日 / 周 / 月 / 全部）中，支持点击卡片以居中模态对话框打开详情（遮罩 + 居中面板），展示至少：标题、时间性质及对应时间、重要程度、紧急程度、分类；描述若存在则展示；关闭模态后用户仍处原视图上下文。
- **FR-002**: 卡片详情 MUST 提供「删除该日程」操作；所有通过界面发起的删除 MUST 经二次确认后执行，确认文案 MUST 明确指向目标卡片；取消则不删除。
- **FR-003**: 界面删除 MUST 复用与对话式删除相同的底层删除能力与确认规则；删除成功后各视图 MUST 及时反映（含标签页激活时的数据拉取策略，与 001 一致）。
- **FR-004**: 月视图 MUST 以当月按周排列的日期网格呈现，每格展示该日日程卡片；卡片过多时 MUST 折叠为「前若干张 + +N 更多」；点击日期格或「+N 更多」 MUST 打开侧滑抽屉列出该日全部卡片，不切换至日视图。
- **FR-004a**: 月视图中跨日持续型卡片 MUST 以跨格连续条带呈现：条带横跨覆盖的全部日期格，完整标题在起始日期格；点击条带任意可见部分 MUST 打开详情。跨月时在各自月份网格内展示对应可见段。
- **FR-005**: 周视图 MUST 以当前所选周七天分列呈现，每列展示当天日程；支持切换上一周 / 下一周 / 回到本周。
- **FR-005a**: 周视图中跨日持续型卡片 MUST 以跨列连续条带呈现：条带横跨覆盖的全部日列，完整标题在起始日列；点击条带任意可见部分 MUST 打开详情。跨周边界时在本周网格内展示对应可见段。
- **FR-006**: 日视图 MUST 以选定日的卡片列表呈现（无需日历网格）；全部视图 MUST 保留 001 的筛选与排序能力。
- **FR-007**: 系统 MUST 在顶部主导航栏提供「+」控件，打开手动创建表单；表单字段 MUST 覆盖卡片核心属性（标题、时间性质及时间、重要度、紧急度、分类；描述可选）。
- **FR-008**: 手动创建 MUST 复用既有卡片创建能力与校验规则（含默认值、时间合法性）；创建成功后新卡片 MUST 在当前视图立即可见。
- **FR-009**: 系统 MUST 在顶部主导航栏提供 AI 助手栏显示/隐藏开关，在所有设备上可用；隐藏时主日程区域 MUST 占满除顶部导航外的可用宽度。
- **FR-010**: AI 助手栏显示时，用户 MUST 可通过拖动分隔边缘调整宽度；宽度 MUST 受最小/最大范围约束；调整结果 MUST 在同一设备上持久记住。
- **FR-011**: 助手栏宽度偏好 MUST 仅保存在当前设备，不跨设备同步；助手栏显示/隐藏状态 MUST 仅在当前浏览器会话内记住（同会话内刷新/切视图保持；关闭浏览器后以新会话打开时恢复默认显示），不写入设备本地持久存储。
- **FR-012**: 主题控件 MUST 仅在浅色与深色之间切换，不再提供「跟随系统」选项。
- **FR-013**: 历史上保存为 system 的主题偏好 MUST 在加载时视为浅色，并 MUST 允许用户正常切换至深色。
- **FR-014**: 主题偏好 MUST 继续多设备共享（与 001 所有者偏好模型一致）。
- **FR-015**: 本轮 MUST NOT 改变 Schedule Card 的数据结构、字段含义或存储格式。
- **FR-016**: 本轮 MUST NOT 改变后端鉴权、增删改查的业务规则；手动操作 MUST 调用与对话操作相同的服务能力。
- **FR-017**: 所有新界面操作 MUST 在已登录会话下执行；未认证用户 MUST NOT 通过新入口绕过鉴权。

### Key Entities

- **Schedule Card（日程卡片）**: 与 001 相同的核心实体；本轮仅改变展示与触达方式，不改变属性定义（标题、描述、时间性质、开始/结束/deadline、重要度、紧急度、分类等）。
- **Schedule View Context（视图上下文）**: 扩展 001 定义：月视图含当前月份、网格布局状态及可选的「日抽屉」打开状态（指向某具体日期）；周视图含当前所选周起止日期；日视图含选定日；全部视图含筛选排序条件。视图上下文只影响展示。
- **Day Schedule Drawer（日日程抽屉）**: 月视图中触发的临时 UI 状态；侧滑展示某一日的完整卡片列表；关闭后用户仍处月视图。非持久实体。
- **Owner Preferences（所有者偏好）**: 在 001 基础上扩展：**主题**仅为 light | dark（system 迁移为 light）；**助手栏宽度**按设备本地存储；**助手栏显隐**仅会话级（非持久偏好）；「即将到期」窗口等既有偏好不变。
- **Card Detail Presentation（卡片详情呈现）**: 用户触发的临时 UI 状态；以居中模态对话框展示单张卡片完整只读信息及删除操作入口；关闭后回到触发时的视图上下文（含月视图日抽屉仍打开的情况）。非持久实体。
- **Manual Create Form（手动创建表单）**: 用户触发的临时 UI 状态，收集与卡片字段对应的输入；提交后经由既有创建流程生成 Schedule Card。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 所有者在任意视图中点击卡片后，3 秒内看到完整详情（含全部必填展示字段）。
- **SC-002**: 通过界面完成一次手动创建（含必填字段）的平均用时不超过 60 秒，且创建后 5 秒内可在当前视图看到新卡片。
- **SC-003**: 月视图与周视图下，95% 的验收测试卡片出现在正确的日期格/列（以人工标注的期望日期为准）。
- **SC-004**: 界面删除与对话删除的二次确认流程 100% 一致（均需确认、均可取消、取消均不删）。
- **SC-005**: 所有者在桌面端隐藏助手栏后，主区域可视宽度增加至少 25%（相对隐藏前）；再次打开后助手栏功能完整可用。
- **SC-006**: 助手栏宽度在同一设备上调整后，刷新或重新打开页面 100% 恢复上次宽度（在允许范围内）。
- **SC-007**: 历史 system 主题用户 100% 可在首次加载后成功切换至 dark，无「无法切换」报告用例。
- **SC-008**: 验收访谈中，所有者对「日历形态月/周视图」与「不依赖对话的增删入口」的主观满意度达到「较首轮明显提升」或等效正面反馈（验收问卷或走查记录）。

## Assumptions

- 本特性为 001-conversational-scheduling 的前端体验迭代；后端 API 与卡片模型已存在且稳定。
- 月视图格子内默认最多展示 3 张卡片摘要，超出部分以「+N 更多」折叠；点击日期格或「+N 更多」打开侧滑抽屉展示该日完整列表（不跳转日视图；具体 N 可在 plan 阶段微调，但 MUST 有折叠机制）。
- 助手栏宽度偏好使用设备本地持久化，不写入跨设备同步的所有者偏好存储；主题偏好仍走所有者偏好多设备共享通道。
- 助手栏显示/隐藏状态仅在同一会话内有效（含会话内页面刷新）；关闭浏览器后以新会话打开时恢复默认显示，与宽度偏好的设备级持久化相互独立。
- 手动创建表单的默认值与校验与 001 对话创建一致：重要度/紧急度默认「中」；未选分类时采用与对话相同的默认分类规则；持续型默认时长 1 小时（若只填开始未填结束）。
- 手动创建表单的分类选择 MUST 使用所有者已有的分类列表（预设 + 对话扩展），本轮不要求在表单内新增分类名（新分类仍可通过 AI 对话添加）。
- 周视图默认以周一为一周起始，与常见日历习惯一致；若部署 locale 不同，plan 阶段可调整但 MUST 在一周七天内连续展示。
- 日视图与全部视图在本轮以「保持列表 + 补齐点击详情」为主，不强制额外日历化改造。
- 卡片详情 MUST 采用居中模态对话框（遮罩 + 居中面板），与日日程侧滑抽屉职责分离；删除二次确认在模态之上或模态内完成。
- 周视图中跨日持续型卡片采用跨列连续条带（起始列完整标题，条带跨越覆盖日列），与月视图跨格条带语义一致。
- 月视图中跨日持续型卡片采用跨格连续条带（起始格完整标题，条带跨越覆盖日期格）；跨月时在各月网格展示对应可见段。

## Dependencies

- **001-conversational-scheduling**: 鉴权、Schedule Card 模型、四种视图入口、对话式 CRUD、删除二次确认、全部视图筛选排序、所有者偏好（含主题）、标签页激活时数据同步。
- **Watson Constitution**: 单用户安全、多设备一致体验（主题共享）、Cursor 式布局、卡片为核心数据单元。

## Out of Scope

- 修改 Schedule Card 字段或新增卡片类型。
- 修改后端 API 契约、鉴权方式或删除确认的服务端语义。
- 手动**编辑**已有卡片（本轮仅补手动**创建**与界面**删除**；修改仍通过 AI 对话）。
- 独立分类管理界面或在手动创建表单中新增分类名。
- 助手栏宽度或显隐状态的跨设备云同步；助手栏显隐的设备级/本地持久化（本轮仅会话级）。
- 恢复「跟随系统」主题选项。
- 提醒推送、第三方日历同步、拖拽改期、AI 主动建议。
