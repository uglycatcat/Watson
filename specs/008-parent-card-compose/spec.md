# Feature Specification: 日程卡片组合与父卡片

**Feature Branch**: `008-parent-card-compose`

**Created**: 2026-07-21

**Status**: Draft

**Input**: User description: "这是 Watson 的第八轮迭代「日程卡片组合与父卡片」。在已上线的 001～007 之上，引入「父卡片」机制，用卡片组合解决标准卡片数量过多时的视图冗余问题：在概览类视图（周/月/全部）里把一组卡片折叠成一张父卡片，在专注当天的日视图里仍摊开显示每张子卡片。"

## Clarifications

### Session 2026-07-21

- Q: 标准卡与父卡如何在同一卡片模型中区分与关联？ → A: 每张卡片有类型（标准 | 父，默认标准）；标准卡可有可选父归属指向至多一个父卡；父卡复用名称与起止时间，标准卡专有属性对父卡不适用。
- Q: 活跃卡片重名如何判定？ → A: 比较前先 trim 再转小写；仅在活跃范围内，父卡名称与标准卡标题互斥不可重名。
- Q: 父卡时间约束与详情校验如何落地？ → A: 父.start ≤ min(子.start) 且 父.end ≥ max(子.end)（仅计已安排子卡）；可更宽不可更窄；详情内改名/改时间就地校验，非法立即提示且不接受。
- Q: 日视图折页角标与完成框如何避免冲突？ → A: 折页在子卡右下角，层级下沉，不得遮挡完成框。
- Q: 全部视图组合拖拽与拖到垃圾箱删除如何共存？ → A: 两者并存，靠松手落点区分——落到卡片为组合，落到右上垃圾箱为删除。

### Session 2026-07-21 (analyze remediation)

- Q: FR-019 恢复加下划线是否与「不改变生命周期」冲突？ → A: 本轮有意变更恢复撞名策略（由 409 改为自动 `_` 前缀）；FR-023 仅保证完成/软删/永久删/未安排/坐标图等语义不变，不含恢复撞名处理。
- Q: 父卡「不具备」重要度等与宪法卡片模型如何兼容？ → A: 父卡持久化层仍写入重要度/紧急度/分类/阶段等占位默认值以满足同表约束，产品与 UI 语义上不适用、不可编辑。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在全部视图把标准卡片组合成父卡片 (Priority: P1)

作为所有者，我希望在「全部」视图中通过拖拽把多张标准卡片收成一张父卡片，以便在卡片很多时减少概览冗余，同时保留每张子卡片的完整信息。

**Why this priority**: 「创建父卡片」是本轮核心价值入口；没有组合能力，后续视图折叠与生命周期均无意义。

**Independent Test**: 准备至少两张活跃标准卡片，仅在全部视图中完成「标准拖到标准 → 确认创建」与「标准拖入已有父卡片」两条路径，确认父卡片出现、子卡片从全部视图消失，且周/月/日以外的既有操作语义不变。

**Acceptance Scenarios**:

1. **Given** 全部视图中有两张独立标准卡片 A、B，**When** 所有者把 A 拖到 B 上并松手，**Then** 弹出「创建父卡片」确认框，列出即将进入该父卡片的卡片，并提供必填名称、默认可改的时间汇总以及取消按钮。
2. **Given** 「创建父卡片」确认框已打开且名称合法（非空、不与任何活跃标准卡片标题或其他父卡片名重名），**When** 所有者确认，**Then** 系统创建父卡片并在全部视图中以该父卡片取代 A、B；A、B 成为其子卡片且不再作为独立条目出现在全部视图。
3. **Given** 「创建父卡片」确认框中名称留空，或 trim/小写后与已有活跃卡片重名，**When** 所有者尝试确认，**Then** 系统拒绝创建并明确提示，不产生父卡片。
4. **Given** 全部视图中已存在父卡片 D，**When** 所有者把一张独立标准卡片拖到 D 上并松手，**Then** 该卡片进入 D，全部视图仍只显示 D（子卡不单独列出），且无需再弹出「创建父卡片」确认框。
5. **Given** 所有者不在全部视图（例如日/周/月视图），**When** 尝试用拖拽把标准卡片组合成父卡片，**Then** 组合不会发生；组合仅在全部视图中可用。
6. **Given** 所有者打开创建流程（点击「+」），**When** 完成创建，**Then** 只能创建标准卡片，不能手动创建父卡片。

### User Story 2 - 合并父卡片并移出子卡片 (Priority: P1)

作为所有者，我希望把两个父卡片合并，并能从父卡片详情中把子卡片拖出恢复为独立卡片，以便灵活调整组合边界而不丢失卡片。

**Why this priority**: 组合后的结构调整（合并与移出）与创建同等关键，决定父卡片能否持续可用。

**Independent Test**: 先形成两个各含至少一张子卡的父卡片，在全部视图把父卡片 A 拖到父卡片 B；再打开 B 的详情把一张子卡拖出详情区，确认合并与移出结果。

**Acceptance Scenarios**:

1. **Given** 全部视图中存在父卡片 A、B，**When** 所有者把 A 拖到 B 上并松手，**Then** A 的全部子卡片并入 B，A 消失且不进入垃圾箱；全部视图只保留 B。
2. **Given** 全部视图中存在父卡片与独立标准卡片，**When** 所有者把父卡片拖到该标准卡片上，**Then** 操作为无效（有禁止态反馈），双方归属不变。
3. **Given** 所有者已打开某父卡片详情且其中有多张子卡片，**When** 把一张子卡片拖出详情区并松手，**Then** 该卡片从父卡片移出，恢复为独立标准卡片并重新出现在各适用视图；父卡片若仍有子卡则继续存在。
4. **Given** 一张标准卡片已属于某父卡片，**When** 所有者查看或操作它，**Then** 它不能同时属于另一个父卡片；父卡片内只能容纳标准卡片，不能再放入父卡片（无多层嵌套）。

### User Story 3 - 管理父卡片时间与已/未安排状态 (Priority: P1)

作为所有者，我希望父卡片时间默认覆盖所有子卡片的时间范围，并允许我在不窄于该范围的前提下手动放宽；同时根据有无时间区分父卡片的已/未安排，以便概览视图按正确分段展示。

**Why this priority**: 父卡片在周/月/全部中的摆放依赖时间与安排状态；边界规则错误会导致日历错位或未安排规则被破坏。

**Independent Test**: 用多张已安排子卡组成父卡片，检查默认包络；手动加宽后再改子卡时间；再准备全部子卡未安排的父卡片，确认父卡片时间为空且仅出现在全部视图的未安排分段。

**Acceptance Scenarios**:

1. **Given** 父卡片内所有子卡片均已安排，**When** 父卡片时间尚未被手调过，**Then** 父卡片开始为所有子卡开始的最小值、结束为所有子卡结束的最大值。
2. **Given** 父卡片时间处于默认包络，**When** 所有者手动把起止调得比包络更宽并保存，**Then** 手调值被保留；之后子卡片时间变化时仍保留该手调值，除非某子卡突破当前父卡片边界，此时父卡片边界被动扩展以覆盖该突破。
3. **Given** 所有者编辑父卡片时间，**When** 尝试把开始调得晚于任一子卡最早开始，或把结束调得早于任一子卡最晚结束，**Then** 系统拒绝该更窄设置并提示约束。
4. **Given** 父卡片内全部子卡片都未安排，**When** 查看父卡片，**Then** 父卡片时间为空，状态为未安排，且仅出现在全部视图（不进入日/周/月日历网格）。
5. **Given** 父卡片有非空起止时间，**When** 查看其安排状态，**Then** 为已安排；有时间为已安排、无时间为未安排。
6. **Given** 子卡片属于某父卡片，**When** 查看或编辑该子卡片，**Then** 子卡片自身的时间、重要度、紧急度、分类、阶段等属性均不因归属父卡片而改变；日视图分区与坐标图定位仍完全按子卡片自身属性计算。

### User Story 4 - 在各视图按规则看到父卡片或子卡片 (Priority: P1)

作为所有者，我希望在周/月/全部看到折叠后的父卡片，在日视图和垃圾箱看到摊开的子卡片（并带归属提示），而二维坐标图完全不受父卡片影响，以便概览精简、专注当日仍可见细节。

**Why this priority**: 差异化呈现是本轮解决「视图冗余」的直接用户收益，也是回归 001～007 时最易出错的边界。

**Independent Test**: 设标准卡 A、B 组成父卡片 D，另有独立卡 C；检查全部、周、月、日、坐标图中的可见性。父详情完整编辑与垃圾箱父名标注分别在 User Story 6 / 5 验收。

**Acceptance Scenarios**:

1. **Given** A、B 属于父卡片 D，C 为独立标准卡片，**When** 打开全部视图，**Then** 显示 D（按其已/未安排进入对应分段）与 C，不单独显示 A、B。
2. **Given** 同上，**When** 打开周视图或月视图，**Then** 按 D 的时间把 D 摆入日历网格（若 D 未安排则不进入周/月），不单独显示 A、B；点击 D 的入口在本故事可先接到详情骨架，完整详情编辑与子卡管理以 User Story 6 验收为准。
3. **Given** 同上且 A、B 与锚定日有交集，**When** 打开日视图，**Then** 不显示 D，照常按各自时间把 A、B 放入「今天截止 / 正在进行 / 今天开始」；A、B 上各有可点击的归属标识（完整打开父详情以 User Story 6 验收）。
4. **Given** 从父卡片进入垃圾箱的标准卡片（完成或删除），**When** 在垃圾箱查看，**Then** 不显示父卡片 D；该标准卡片显示时标注其原属父卡片名称（标注数据依赖完成/删除时写入的父名快照，与 User Story 5 一并验收）。
5. **Given** 任意时刻，**When** 查看二维优先级坐标图，**Then** 仅按标准卡片的重要度/紧急度定位，不出现父卡片；独立卡 C 在所有场景行为与本轮之前一致。

### User Story 5 - 父卡片随子卡清空而消失，并正确恢复归属 (Priority: P2)

作为所有者，我希望父卡片没有「删除」「完成」入口，只通过子卡移出/完成/删除而减少，减到零时自然消失；从垃圾箱恢复曾属某父卡片的标准卡时能归回或重建同名父卡片，以便组合关系与软删语义自洽。

**Why this priority**: 生命周期与垃圾箱恢复决定数据不会留下「空壳父卡片」或孤儿归属，但依赖组合与视图已可用。

**Independent Test**: 对仅含两张子卡的父卡片分别移出、完成、删除直至清零；再从垃圾箱恢复曾属已消失父卡片的子卡，确认重建与重名加下划线规则。

**Acceptance Scenarios**:

1. **Given** 某父卡片，**When** 所有者查看其可用操作，**Then** 可编辑名称/时间并管理子卡，但不提供「删除」或「完成」父卡片的操作。
2. **Given** 父卡片仅剩 1 张子卡片，**When** 所有者不继续移出或归档该子卡，**Then** 父卡片仍然存在（不因只剩一张而自动解散）。
3. **Given** 父卡片内子卡片经移出、完成或删除减到 0 张，**When** 最后一张离开父卡片，**Then** 父卡片立即消失且不进入垃圾箱。
4. **Given** 子卡片被完成或删除，**When** 该操作发生，**Then** 子卡片按既有语义进入垃圾箱，并同时从父卡片移除；若因此清零则父卡片消失。
5. **Given** 垃圾箱中有曾属于父卡片「项目X」的标准卡片，且活跃视图中仍存在同名父卡片「项目X」，**When** 所有者恢复该标准卡片，**Then** 它直接归回现存的「项目X」。
6. **Given** 同上但同名父卡片已不存在，**When** 所有者恢复该标准卡片，**Then** 系统自动重建同名父卡片（时间按当前子卡片重新汇总）并将该卡归入。
7. **Given** 从垃圾箱恢复任一张卡片（标准或经重建产生的父卡片场景）时，其名称与现有活跃卡片重名，**When** 执行恢复，**Then** 系统在名称前自动加下划线前缀；若仍重名则继续递增下划线直至不再重名。

### User Story 6 - 打开并编辑父卡片详情 (Priority: P2)

作为所有者，我希望从全部视图点击父卡片，或从日视图点击子卡归属标识，都能打开同一父卡片详情，以便改名、在约束内改时间，并按创建顺序管理子卡列表。

**Why this priority**: 详情是管理组合的唯一集中入口；入口一致可降低学习成本。

**Independent Test**: 分别从全部视图点击父卡片、从日视图点击归属标识打开详情，修改名称与合法时间，确认子卡按全局创建时间排列且拖出可移出。

**Acceptance Scenarios**:

1. **Given** 全部视图显示父卡片 D，**When** 所有者点击 D，**Then** 打开 D 的详情页。
2. **Given** 日视图中某子卡片显示归属标识，**When** 所有者点击该标识，**Then** 打开同一父卡片详情页（与从全部进入的为同一对象）。
3. **Given** 父卡片详情已打开，**When** 所有者修改名称（必填；与活跃标准标题或其他父卡片重名——比较前 trim 并转小写）或输入非法值，**Then** 就地提示且不接受保存；合法名称保存后立即生效。
4. **Given** 父卡片详情已打开，**When** 所有者在时间约束内修改起止并保存，**Then** 新时间生效；违反「父.start ≤ min(子.start) 且 父.end ≥ max(子.end)」的更窄修改就地拒绝。
5. **Given** 父卡片含多张子卡片，**When** 查看详情中的子卡列表，**Then** 子卡片按全局创建时间排列，并可拖出详情区以移出。

---

### User Story 7 - 识别父卡片与拖拽反馈 (Priority: P3)

作为所有者，我希望父卡片在视觉上明显区别于标准卡片（堆叠影、子卡计数徽章、无标准卡专有元素），日视图子卡有折页角标，拖拽组合/移出全程有清晰反馈，并尊重「减少动态效果」与明暗主题对比度，以便扫视与操作都可预期。

**Why this priority**: 视觉与动效提升可感知性，但不改变业务语义；可在核心流程之后完善。

**Independent Test**: 在明/暗主题下对比父卡与标准卡外观；走完拖起、悬停高亮/禁止、松手收拢与成功提示；开启系统减少动态效果后重复。

**Acceptance Scenarios**:

1. **Given** 全部或周/月视图中的父卡片，**When** 所有者扫视，**Then** 以「一叠卡片」堆叠影区分于标准卡，右上角计数徽章显示当前子卡数量，且不显示重要度/紧急度、分类、阶段、完成等标准卡专有元素。
2. **Given** 日视图中属于某父卡片的标准卡片，**When** 查看该卡，**Then** 右下角有可点击的折页角标作为归属标识，且该角标层级下沉、不遮挡完成框。
3. **Given** 所有者在全部视图进行可组合拖拽，**When** 拖起、悬停有效目标、悬停父卡片、悬停无效目标、松手完成，**Then** 分别出现浮动、目标高亮、计数递增预览、禁止态、被合并卡片向父卡收拢及轻量成功提示。
4. **Given** 全部视图中同时存在组合落点与右上垃圾箱落点，**When** 所有者拖起一张卡片，**Then** 松手落到另一张卡片（或父卡片）时走组合语义，松手落到右上垃圾箱时走既有删除语义；两者靠落点区分、互不替代。
5. **Given** 系统开启「减少动态效果」，**When** 执行上述拖拽或过渡，**Then** 动效被减弱或跳过，但不影响操作结果可达。
6. **Given** 深色主题，**When** 查看堆叠影与折页角标，**Then** 对比度足够可读；明暗主题与既有强调色体系保持一致。

### Edge Cases

- 创建父卡片时取消确认框：不创建父卡片，被拖拽的标准卡片保持原位与独立状态。
- 父卡片拖到标准卡片、或在非全部视图尝试组合：无效，数据不变。
- 全部子卡未安排：父卡片时间为空、未安排，仅进全部视图。
- 手调父卡时间后子卡整体缩回包络内：保留手调更宽时间，不自动收窄。
- 子卡时间突破父卡边界：父卡被动扩展以覆盖；不自动缩小。
- 父卡仅剩 1 张子卡：父卡仍存在；减到 0 才消失且不进垃圾箱。
- 恢复时活跃侧已有同名标准卡或父卡：按递增下划线前缀消解重名后再恢复/重建。
- 一张标准卡不可属于多个父卡；不可把父卡放入父卡（两层封顶）。
- 全部视图拖到卡片 vs 拖到右上垃圾箱：落点决定组合或删除，二者并存。
- 坐标图、独立标准卡 C、标准卡「+」创建、AI 不操作日程、单用户鉴权：本轮均不改变。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 仅支持两种日程卡片类型：标准（默认）与父。标准卡片保留 001～007 全部既有属性与生命周期；父卡片在产品语义上仅暴露名称、开始时间、结束时间、已/未安排状态；标准卡专有属性（重要度/紧急度、分类、阶段、完成等）对父卡片不适用（持久化可存占位默认值以满足同表约束，见 Assumptions）。
- **FR-002**: 标准卡片 MUST 只能通过既有「+」手动创建路径创建；父卡片 MUST NOT 允许通过「+」或等价手动创建入口创建，MUST 仅能通过全部视图拖拽组合产生。
- **FR-003**: 一张标准卡片同时 MUST 最多属于一个父卡片（通过可选父归属表达；无归属即为独立卡）；父卡片 MUST 只能容纳标准卡片；MUST NOT 允许多层嵌套。
- **FR-004**: 卡片组合 MUST 仅在全部视图通过拖拽完成，且 MUST 支持：标准→标准（经「创建父卡片」确认后新建）、标准→已有父卡片（直接加入）、父卡片→父卡片（源父全部子卡并入目标父，源父消失且不进垃圾箱）。
- **FR-005**: 父卡片拖到标准卡片 MUST 为无效操作并给出禁止态反馈；非全部视图 MUST NOT 完成组合。
- **FR-006**: 「创建父卡片」确认框 MUST 包含：必填且不可重名的名称、默认自动汇总且可手改的时间、即将进入该父卡片的卡片列表、取消按钮；取消 MUST 不产生父卡片。
- **FR-007**: 所有者 MUST 能在父卡片详情中把子卡片拖出详情区以移出；移出后该卡恢复为独立标准卡片并重新出现在各适用视图。
- **FR-008**: 父卡片默认时间 MUST 等于所有已安排子卡片时间的包络（开始取最小、结束取最大）；全部子卡未安排时父卡片时间 MUST 为空。
- **FR-009**: 父卡片时间 MUST 满足 父.start ≤ min(已安排子.start) 且 父.end ≥ max(已安排子.end)；所有者 MUST 能调得比包络更宽，MUST NOT 能调得更窄；手调后 MUST 保留手调值，仅当子卡突破当前边界时被动扩展。
- **FR-010**: 父卡片已/未安排状态 MUST 由时间推导：有起止时间为已安排，无时间为未安排；未安排父卡片 MUST 仅出现在全部视图，MUST NOT 进入日/周/月日历网格。
- **FR-011**: 父卡片 MUST NOT 改变子卡片自身任何属性；子卡片 MUST 仍按其自身时间参与日视图分区，并按其自身重要度/紧急度参与坐标图定位。
- **FR-012**: 全部与周/月视图 MUST 显示父卡片、MUST NOT 单独显示其下标准子卡；日视图 MUST NOT 显示父卡片，MUST 摊开显示子卡并提供可点击归属标识；垃圾箱 MUST NOT 显示父卡片，从父卡进入的标准卡 MUST 标注原属父卡片名称；坐标图 MUST NOT 出现父卡片。
- **FR-013**: 父卡片 MUST NOT 提供「删除」或「完成」操作；MUST 支持编辑名称/时间与管理子卡。
- **FR-014**: 当父卡片子卡数减至 0（经移出、完成或删除）时，父卡片 MUST 立即消失且 MUST NOT 进入垃圾箱；仅剩 1 张子卡时父卡片 MUST 仍然存在。
- **FR-015**: 子卡片被完成或删除时 MUST 按既有语义进入垃圾箱，并同时从父卡片移除；若因此清零则父卡片按 FR-014 消失。
- **FR-016**: 从全部视图点击父卡片，或从日视图点击子卡归属标识，MUST 打开同一父卡片详情；详情 MUST 支持改名（必填、不可重名）、在约束内改时间、按全局创建时间排列并管理子卡列表；名称与时间校验 MUST 就地执行，非法输入立即提示且不得保存。
- **FR-017**: 父卡片名称与标准卡片标题 MUST 在活跃卡片范围内互斥不可重名；重名比较 MUST 先 trim 再转小写后再判定。
- **FR-018**: 从垃圾箱恢复曾属于某父卡片的标准卡片时：若同名父卡片仍存在则 MUST 归回该父卡片；若不存在则 MUST 自动重建同名父卡片（时间按当前子卡重新汇总）后归入。
- **FR-019**: 从垃圾箱恢复标准卡片时，若其名称与现有活跃卡片重名，MUST 自动在名称前加下划线前缀，仍重名则继续递增下划线直至不再重名（本轮有意取代既往恢复冲突返回错误的行为）。
- **FR-020**: 父卡片视觉 MUST 以堆叠影与右上角子卡计数徽章（显示当前子卡数）为核心识别，且 MUST NOT 显示标准卡专有的优先级/分类/阶段/完成等元素；日视图归属标识 MUST 为右下角可点击折页角标，且 MUST 层级下沉、不遮挡完成框。
- **FR-021**: 拖拽组合与移出全过程 MUST 提供拖起浮动、有效目标高亮、悬停父卡时计数递增预览、无效目标禁止态、松手收拢与轻量成功提示；所有动效 MUST 尊重系统「减少动态效果」偏好；明暗主题下堆叠影与折页 MUST 保持可读对比度。
- **FR-022**: 全部视图中，组合拖拽与既有「拖到右上垃圾箱删除」MUST 并存：松手落点为卡片（含父卡片）时走组合语义，落点为右上垃圾箱时走既有删除语义；MUST NOT 用组合取代删除手势。
- **FR-023**: 本轮 MUST NOT 改变单用户鉴权、AI 不操作日程、标准卡片的完成/软删/永久删除与未安排规则、二维坐标图既有行为；MUST NOT 把父卡片纳入垃圾箱。恢复时的撞名自动加下划线（FR-019）与父卡归属归回/重建（FR-018）为本轮有意扩展，不视为对「生命周期不变」的违反。除上述明示扩展外，001～007 已交付能力 MUST 可逐项回归无损。

### Key Entities

- **日程卡片（Schedule Card）**：统一卡片记录；具有类型「标准」或「父」（默认标准）。父类型记录复用名称与起止时间；标准类型专有字段对父类型在产品语义上不适用。
- **标准卡片（Standard Card）**：类型为标准的日程卡片；可独立存在，也可通过可选父归属指向至多一个父卡片；属性与完成/删除/垃圾箱语义不变（恢复撞名策略见 FR-019）。
- **父卡片（Parent Card）**：类型为父的容器记录；产品可编辑属性为名称、开始、结束、已/未安排；重要度/紧急度/分类/阶段等以占位默认值持久化但不暴露编辑；无删除/完成；子卡数为 0 时消失且不进垃圾箱。
- **归属关系（Membership）**：标准卡片上的可选父归属（指向所属父卡片，可空）；决定概览折叠、日视图摊开与垃圾箱标注/恢复归回；一子一母、两层封顶。
- **创建父卡片确认**：组合路径中的一次性确认交互，携带名称、时间汇总与待纳入卡片列表。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 所有者在全部视图中可将至少两张标准卡片组合成父卡片，并在 1 分钟内完成「拖拽 → 命名确认 → 看到父卡片取代子卡」的主路径。
- **SC-002**: 在含父卡片的数据集上，周/月/全部中同一组子卡不以独立条目重复出现；日视图中同一组子卡均可见且父卡片本身不出现——抽查 10 组组合，可见性规则符合率 100%。
- **SC-003**: 父卡片时间约束（不可窄于子卡包络、手调保留、突破才扩展、全未安排则时空）在预置边界用例中正确率 100%。
- **SC-004**: 父卡片清零消失、剩一仍存、垃圾箱恢复归回/重建、重名下划线规则，在预置生命周期用例中正确率 100%，且空壳父卡片不会残留在任何视图。
- **SC-005**: 首次使用组合的所有者中，至少 90% 能在无说明文档的情况下独立完成一次组合与一次移出（可用性抽测或走查）。
- **SC-006**: 开启系统「减少动态效果」时，组合/移出仍可完成且无障碍；明暗主题下父卡堆叠影与折页角标可辨认。
- **SC-007**: 001～007 既有核心场景（创建/编辑标准卡、日周月全部、完成删除恢复、坐标图、分类阶段日报等）回归清单全部通过，无功能回退。

## Assumptions

- 本轮在既有单用户、会话鉴权、AI 纯对话不写日程的产品边界内交付；不引入多用户或协作共享父卡片。
- 「活跃卡片」指未进入垃圾箱（未完成且未删除）的标准卡片与仍存在的父卡片；重名互斥与恢复加下划线均针对活跃范围；重名比较为 trim 后转小写。垃圾箱内历史名称不阻塞新活跃名称。
- 「全局创建时间」指标准卡片自身的创建时间顺序，用于父卡片详情内子卡列表排序。
- 父卡片合并（A→B）后保留目标父卡片 B 的名称与（在合法前提下）当前时间设定；若并入子卡突破 B 的当前边界则按 FR-009 被动扩展。
- 「创建父卡片」确认框中的默认时间：若待纳入卡片中存在已安排者，取这些已安排卡片的时间包络；若全部未安排，则时间为空。
- 卡片类型与父归属是同一卡片模型上的区分与关联方式；持久化可含 `kind` / `parentId` / 手调标记 / 进箱父名快照等，以 plan/data-model 为准。
- 为满足同表与宪法「日程卡片」字段完备性，父卡创建时写入重要度/紧急度默认值、`categoryId=system-none`、默认阶段等占位；UI 与父卡编辑 API 不得把它们当作可操作语义。
- 拖拽成功提示为轻量、非阻断式；具体文案可在实现时选用简短中文提示，不影响本规格验收。
- 动效时长与减弱策略延续第七轮「尊重减少动态效果」的产品约定；本轮不另定强制毫秒数。
- 二维坐标图、标准卡完成/软删/永久删除、未安排仅进全部、拖到右上垃圾箱删除等规则保持不变；**恢复撞名由报错改为自动加 `_`** 与 **父归属归回/重建** 为本轮明示扩展（见 FR-018/019/023）。
- 回归范围覆盖 001～007 的用户可感知行为（含上述明示扩展的新期望）；不要求改写历史 feature 文档。
