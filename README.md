# Watson

> 一个 **AI 深度集成的个人日程管理系统**。单用户、公网部署、多设备浏览器随时随地访问。
> 交互形态对标 **Cursor**：主区域是日程视图，侧边是一个 AI 聊天栏——你用自然语言跟 AI 对话，AI 直接帮你增删改查日程。

---

## 一、产品定位（Product Vision）

Watson 是**为「我自己」一个人打造的**智能日程中枢。它不是团队协作工具，也不是通用日历应用；
它的核心价值是：**用一句话就能管理日程**——把「明天下午三点跟张总开会，很重要」这样的自然语言，
交给侧边 AI 聊天栏，由 AI 理解并落地为一张结构化日程卡片，省去手动填表单的摩擦。

**一句话概括**：Cursor 式交互 × 个人日程管理 × 随身可达的私有服务。

### 目标用户
- **唯一用户**：项目所有者本人。
- **多设备**：手机 / 平板 / PC，均通过浏览器直接访问，无需安装 App。
- **随时随地**：部署在公网服务器，出门在外也能查看和调整日程。

### 核心问题（要解决的痛点）
1. 传统日历建日程要点开表单、逐字段填写，**摩擦大、录入慢**。
2. 缺少一个能「对话式」管理日程的入口——想改个安排还要翻菜单。
3. 个人日程散落多设备，缺一个**私有、安全、随身**的统一入口。

## 二、核心功能（Core Features）

### 1. 日程卡片（Schedule Card）——数据核心
日程以**卡片**为基本单位存储与分类。每张卡片的基础属性：

| 属性 | 说明 |
|---|---|
| **时间性质** | 二选一：① **持续型**（有开始时间 + 结束时间）；② **截止型**（只有一个 deadline） |
| **重要程度** | 分级（如 高/中/低），用于排序与视觉标识 |
| **紧急程度** | 分级（如 高/中/低），与重要程度共同构成「四象限」优先级 |
| 标题 / 描述 | 卡片内容 |
| 分类 | 用于筛选与归组 |

> 「重要 × 紧急」两个维度是刻意设计的——它让 AI 和视图都能按优先级智能排序，而不只是按时间排。

### 2. 多种日程视图（Views）
- **日视图**：单日时间轴。
- **周视图**：一周概览。
- **月视图**：整月日历。
- **全部视图**：把所有日程卡片平铺展示，配备**筛选器**（按分类/重要度/紧急度/时间性质）和**排序器**（按时间/优先级）。

### 3. AI 聊天栏（AI Chat Panel）——交互核心 ⭐
- 界面对标 Cursor：**侧边常驻一个聊天栏**。
- 用户用**自然语言**跟 AI 对话，AI 据此对日程数据执行操作：
  - **添加**：「下周一上午十点体检」→ 自动建卡并填好时间/性质。
  - **查询/问答**：「我这周三有什么安排？」「最近有没有 deadline 快到了？」
  - **修改**：「把周会改到下午四点」。
  - **删除**：「取消明天的牙医预约」。
- AI 的能力**通过用户自行配置的 LLM API Key 驱动**（见下）。

### 4. LLM 接入（可配置，对标 Hermes）
- **不绑定**任何单一模型或中转。用户在**使用时自行配置** API Key。
- 支持切换 **provider**：OpenAI / Anthropic (Claude) / DeepSeek 等 OpenAI-兼容接口。
- 配置项（如 `API_KEY` / `BASE_URL` / `MODEL` / `PROVIDER`）一律**外置**到 `config.yaml` 或 `.env`，
  **不硬编码、不纳入版本控制**；提供脱敏的 `config.example.*`。

## 三、非功能性需求（Non-Functional Requirements）

### 1. 安全与访问控制 🔒（硬性要求）
> 这是本项目的**一等公民需求**，不是附加项。

- 系统部署在**公网**，但**必须只有所有者本人能访问**。
- 登录页输入 **四字符验证码**（默认 `ANNA`），校验通过后建立 HttpOnly 会话；错误则框体变红并重试。
- 生产环境可通过环境变量 `WATSON_ACCESS_CODE` 覆盖默认验证码。
- 需支持**多设备**登录（手机/平板/PC），但都归属于同一个人。
- **已移除**长随机访问令牌与 `watson:init` 初始化流程。

### 2. 平台与技术栈
- **Node.js** 全栈框架。
- 包含 **Web 前端 + 后端** 完整设计。
- 浏览器直接访问，无原生 App。

### 3. UI / 美术风格
- **控件排布仿照 Cursor**。
- 布局：**顶部控制栏** + 其余为**主视觉区**（含视图区与侧边 AI 聊天栏）。
- 支持**明 / 暗两种主题**。

## 四、MVP 范围建议（Scope for v1）

为了让第一轮 Spec Kit 能收敛，建议 v1 聚焦：

**必做（In Scope）**
- 日程卡片的 CRUD（含两种时间性质 + 重要/紧急分级）。
- 日 / 周 / 月 / 全部 四种视图（全部视图带筛选与排序）。
- 侧边 AI 聊天栏：自然语言完成日程的增 / 删 / 改 / 查。
- 可配置 LLM provider（至少跑通一个 OpenAI-兼容接口）。
- 单用户访问控制（登录鉴权 + 会话）。
- 明暗主题 + Cursor 风格布局。

**暂不做（Out of Scope，v1 后再议）**
- 多用户 / 协作 / 共享。
- 主动智能（自动排期、冲突检测、习惯学习）——先做「你说 AI 做」，不做「AI 主动建议」。
- 第三方日历同步（Google/Outlook）。
- 提醒推送 / 通知。

## 六、约定

- 密钥 / LLM API Key / 服务地址放入 `config.yaml` 或 `.env`，**不纳入版本控制**（见 `.gitignore`），并提供脱敏的 `config.example.*`。
- 访问验证码默认 `ANNA`；生产环境建议设置 `WATSON_ACCESS_CODE` 与强 `SESSION_SECRET`。
- `.cursor/` 已加入 `.gitignore`（可能含凭证）。

## 七、环境

- Spec Kit CLI 通过 `uvx --from git+https://github.com/github/spec-kit.git specify ...` 运行（`uv` 在 `~/.local/bin`）。
- Node `v22`、git 已就绪。
